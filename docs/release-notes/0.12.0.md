# Release notes — 0.12.0

`0.12.0` carries the whole of the spec-driven-development migration: fourteen area passes between
2026-09-01 and 2026-09-06, plus the close-out work that followed. Every area of the SDK now has a
current-truth spec page under [`docs/specs/`](https://github.com/VION-IoT/dale-sdk/blob/main/docs/specs/), and each pass fixed the defects it found
while it wrote the page down. That is why one release carries far more behaviour change than the
five before it put together.

Most of it is the same shape: **something that used to fail silently now refuses, and says why.**
A call that was dropped, a declaration that bound nothing, a payload that was fabricated from a
truncated buffer, a write that reported success on a block that never applied it. Each of those is
better as a refusal, and each of them can redden a build or surface an exception where nothing
happened before.

**Read [`docs/migrations/0.12.0-spec-pass-behaviour-changes.md`](https://github.com/VION-IoT/dale-sdk/blob/main/docs/migrations/0.12.0-spec-pass-behaviour-changes.md)
before you bump.** It carries the recipes, and the one thing you have to change *before* the bump
rather than after it.

---

## Before you bump: dual-annotated measuring points

A member declaring both `[ServiceProperty]` and `[ServiceMeasuringPoint]` used to have *both*
streams throttled from the `[ServiceProperty]`'s knobs; the measuring point's own `MinInterval`,
`MinChange` and `Immediate` were read and ignored. Each stream now reads its own attribute, so a
`[ServiceMeasuringPoint]` that declares no knobs falls to the attribute defaults — `MinInterval =
"250ms"`, no deadband, not immediate.

That is a rate increase, not a loss of data, but it is a rate increase you did not ask for. Declare
an explicit `MinInterval` on every dual-annotated `[ServiceMeasuringPoint]` before you take the
bump. The migration page has the sweep.

## Declarations that used to compile

These fire in *your* build. Severity is marked on each, because it decides whether you find out at
the bump or at first start:

- **`DALE043`** *(Error)* reaches component types. `[IncludedWhen]` on a type that is not a logic
  block, or on any member of one, was accepted and did nothing.
- **`DALE005`** *(Error)* rejects a `[Timer]` interval that is `NaN`, infinite, longer than
  4294967 seconds, or positive but shorter than one clock tick (100 ns). Such a block used to build
  and then throw at configuration.
- **`DALE012`** *(Warning)* rejects a base-class and a derived-class `[Timer]` that resolve to one
  identifier. One of the two silently never ticked. **A warning is easy to miss and this one now
  has teeth** — the configuration refuses the same declaration at start.
- **`DALE041` / `DALE042`** *(Error)* now judge an abstract block's `VisibleWhen` predicates, so a
  typo in a library's base block surfaces in the library's own build instead of only in its
  consumer's.
- **`DALE047`** *(Warning)* flags a `[Command]`, `[StateUpdate]` or `[RequestResponse]` struct
  declared beside its contract class rather than nested in it — the generator read nothing there.
- **`DALE048`** *(Error)* rejects a blank `[ServiceProviderContractType]` token, which used to reach
  the introspection document as a contract type with no name.
- **`DALE013`** *(Warning)* fires again on an `internal [PublicApi]` type with no `<summary>`, and
  `DALE013`/`DALE014` judge public types nested in public types.
- **`DALE033`** *(Warning)* judges **every** emission attribute of a dual-annotated member rather
  than the first one it finds, and judges a `[StructField]`'s `StringFormat` as well.
- **`DALE020`** *(Error)* reads a unit off whichever emission attribute states one. This is the
  **multi-interface** conflict rule, not the dual-annotation one: it fires where two interfaces
  declare the same service-element name with different units, and it stays silent where the
  implementing class states its own emission attribute. What changed is that a unit stated on a
  `[ServiceMeasuringPoint]` now counts, so a conflict that was invisible is seen.
- **`[Presentation]` is properties-only and `[StructField]` is constructor-parameters-only.** Both
  were declarable in a second place no reader ever looked at, where they emitted nothing and warned
  about nothing.

And `dotnet pack` / `dale build` now refuse an artifact rather than shipping one that cannot work:
a logic block missing from its plugin's `IConfigureServices`; a gate predicate that does not parse
or that names something the block does not declare as an `[InstantiationParameter]`; a blank or
duplicated endpoint identifier.

**Diagnostics that stopped firing.** `DALE001` no longer fires on a contract-typed property on an
**interface**, where its remedy was a compile error. `DALE026` no longer warns on a `Group` key
matching a platform `PropertyGroup` constant — it had fired on every consumer since it shipped.
`DALE020` no longer fires when the resolving attribute sits on a base class — the other half of the
same fix that made it read whichever emission attribute states a unit. `DALE015` credits every
matching namespace prefix. A non-public `[InstantiationParameter]` draws one `DALE044` where it drew
three. `DALE033` and `DALE040` stop firing on a `[StructField]` written on a **method's** parameter or a
**class** constructor's parameter, neither of which any schema is built from. A **struct**
constructor's parameter — the one site a reader does reach — is judged as before.

## Configurations that used to start

- **A `[Timer]` the binder cannot schedule is refused at start, naming the method** — a duplicate
  identifier, a blank one, an interval that is not a number, infinite, longer than a real clock can
  wait, or shorter than one clock tick. A block that shipped past a suppressed `DALE012` now fails.
- **A `[ServiceProviderContractBinding]` on a property whose type carries no
  `[ServiceProviderContractType]`, a `[LogicBlockInterfaceBinding]` whose `ForInterface` the type
  does not implement, and one on a non-public property** are each refused. All three bound nothing
  and reported nothing, so a block ran with a null or a topology addressed an identifier that was
  never minted.
- **A second configuration of a live block throws**, naming the documented contract that changing a
  parameter re-activates and recycles the block. It used to be applied additively, so a gate
  flipping closed left its member bound.
- **A runtime write to an `[InstantiationParameter]` is refused** and answered with the unchanged
  value, matching the attribute's documented "never settable at runtime".
- **A blank or duplicated endpoint identifier fails block start as well as the pack**, naming the
  declarations. A blank one addressed nothing; a duplicated one silently dropped whichever binding
  bound first.

**And two that now start where they did not.** A contract-typed property declared
`{ get; private set; }` on a base class binds. A `[Timer]` or `[Persistent]` declared **private on a
base class** is now discovered — so a base class that scheduled its own cycle starts ticking, and
one that kept private state starts persisting. Both were silently inert at every door.

## Behaviour that changed without you asking

- **A malformed inbound I/O payload is dropped, not decoded.** Every digital and analog state decode
  verifies the buffer against its schema first. An empty payload used to throw out of the handler; a
  payload truncated in flight used to deliver a **fabricated value** to every bound block.
- **The HTTP client's own timeout ceiling arrives as `TimeoutException`.** It expired as
  `TaskCanceledException` while a per-request timeout expired as `TimeoutException`, so a block
  catching only the latter missed every expiry of the ceiling — including every request that set no
  per-request timeout at all. Both now carry a message naming whichever bound elapsed.
- **A failure raised after a per-request timeout elapsed keeps its own class.** A body that would
  not parse, a broken stream, a 502 judged late: each used to be reported as a `TimeoutException`.
- **Three silent HTTP losses became named refusals at the caller** — a null dispatcher, a timeout
  outside the band the runtime accepts, and a `SendRequest` given a null request or `RequestUri`.
  A response-bearing member given a null success callback schedules nothing instead of queueing an
  action that throws inside the block's actor.
- **A failed HTTP request no longer leaks its response**, and neither does `SendRequest` with no
  success callback.
- **A per-request `timeout` never overrode the client's ceiling, and eleven doc sites said it did.**
  The two stack and the smaller wins. No signature changed; the shipped documentation did, and so
  should any belief built on it.
- **`AddDaleHttpSdk` survives a double registration.** Two calls used to send the User-Agent twice.
  Each default is now applied only where the client still lacks it, so a second registration no
  longer runs the default User-Agent and the 30 s timeout over a value an earlier registration's
  `configureClient` had chosen. The last `configureClient` still wins for whatever it sets itself.
- **A second start or a second stop is acknowledged and does nothing.** A second start used to run
  the hook again, republish every value and arm a second periodic-save chain, so a block started
  twice wrote its snapshot twice a minute for the life of the process. A stop and a restart inside
  the save interval had the same effect.
- **A stop-hook exception reaches the host's health surface** after the acknowledgement, instead of
  being logged and swallowed inside the block.
- **A linked-interface map arriving before the configuration is applied, not dropped** — held and
  applied at the configuration's tail, after the ready hook, which is where the hook contract says a
  block may read its links. A second such map no longer discards the first.
- **The acknowledgement and termination waits count each actor's answer once**, and count an actor
  a caller listed twice once. A second acknowledgement from one actor used to satisfy a silent
  actor's share, and the termination wait used to time out on a duplicated list.
- **A negative acknowledgement or termination timeout is refused where it used to hang** — the
  temporary actor restarted in a loop and the caller's `await` never returned at all.
- **A delayed action's over-long delay is refused and a negative one is clamped to nothing.** Both
  used to throw out of the handler, where the middleware swallowed it — so a block silently lost the
  reschedule that kept its cycle alive. The refusal now names `InvokeSynchronizedAfter` rather than
  only the `delay` parameter and the bound.
- **The contract-identity parse throws the SDK's own typed topic exceptions, naming the topic**,
  where it threw an undocumented `ArgumentOutOfRangeException` naming neither. The parse runs inside
  the sealed dispatch, so no handler could have caught the old type. A topic that is long enough but
  sits under another prefix is now a `TopicSubstringNotFoundException` rather than three segments
  read at the wrong offset and a frame forwarded nowhere.
- **A publish with no explicit content type carries `application/x-flatbuffers`**, as its own
  documentation and every shipped handler already said.
- **A contract message to an unbound contract is skipped with a warning** where it threw, recorded a
  handler exception and counted a vitals error.

## Modbus

`ModbusProtocolLimits` and `ModbusTimeoutLimits` are published, and the client refuses past them
before the wire — 125 registers to read, 123 to write, 2000 bits to read, 1968 to write, and a
timeout above just under 25 days. A `quantity` of zero is refused the same way — as a `count` of
zero already was — where it used to be dispatched and come back a code-less frame fault that closed
the socket.

`Port` refuses 0 on the TCP client and the hosted server. `ConnectionTimeout` and
`DefaultOperationTimeout` refuse a non-positive duration on both transports — a zero connect timeout
used to fault every connect and arm a backoff against a device that was answering. `MaxQueuedAge`
refuses zero or negative on the queue, where the "no limit" sentinel used to swallow it and mean the
opposite. `QueueCapacity` and `QueueOverflowPolicy` throw when changed after the queue exists, and
`QueueOverflowPolicy` refuses a value outside the declared set. The enable is transactional, so a
queue that cannot be built leaves the client disabled rather than enabled with no queue behind it.

A request still queued when the client is disposed completes with a `Cancelled` receipt instead of
vanishing. `DefaultOperationTimeout` is bound when the call is accepted, as it was always
documented. A disposed client and a disposed server both read `IsEnabled == false`.
`ConnectBackoffMax = TimeSpan.MaxValue` no longer overflows the clock when a backoff is armed.

## The `dale` command-line tool

- **The tool cautions when it is older than the SDK the project references**, naming both versions
  and the `dotnet tool update` line that fixes it. A stale global tool used to render the previous
  release's view of a project that had already moved on, with nothing in the output saying which
  half was old. It is a warning, so `--output json` is unaffected.
- **`--output json` emits JSON and nothing else.** Every child process the tool starts has its
  standard output relayed to standard error, so `dale list --output json` and `dale pack --output
  json` no longer print MSBuild's restore banner in front of the document.
- **A table-mode failure goes to standard error.** JSON mode is unchanged: `{"error": …}` stays on
  standard output, where a single-stream parser expects it.
- **Four paths that printed no document now print one**, where they emitted nothing at all, an
  unparseable line, or a banner in front of one: `dale whoami --output json`
  (`{email, integrators, environment, expiresAt}`), `dale --version --output json`
  (`{"version": "<version>"}`, verified against the built tool), `dale upload --output json`, and
  the `dale add` annotate path (the create path's shape plus `annotated`).
- **`dale login` and `dale config set-integrator` refuse rather than prompt in JSON mode**, naming
  the memberships and the option that chooses one; `set-integrator` now *has* that option
  (`--integrator-id`) and selects a single membership without asking.
- **A stored login is used only against the environment it was minted for.** `dale upload
  --environment production` with a `test` login used to send the test token to production and report
  "Session expired. Run `dale login` again" — the one instruction that could not fix it.
- **`dale build --project X` and `dale test --project X` build X**, not the solution above the
  working directory; a `--project` that cannot be used is refused rather than worked around.
- **`dale upload` matches its package by exact id**, so two packages in one directory no longer race
  for whichever was newest under whichever id.
- **`scenario schema` and `scenario scaffold` take their file with `--out`/`-O`.** `-o` stays as a
  short form for one release. `--output` is global-only now, so `dale scenario schema --output json`
  prints the schema rather than writing a file named `json`.
- **`scenario validate` refuses a directory holding no scenario file**, where it reported
  "Validated 0 scenario file(s)" and exited 0 — which made a rename-catching CI gate pass while
  checking nothing.
- **`dale dev --export-config` exits 0 when the export was written**, whatever the host's own exit
  code, and both `dale dev` branches announce what they will actually do rather than promising a
  server either way.
- **`dale add` refuses every name and `--type` before writing anything**, writes numbers
  invariantly, can produce a dual-annotated member, and preserves the file's line endings and
  byte-order mark outside the lines it inserts.
- **`dale login -h` no longer prints a machine-dependent default** for `--environment`; the
  description states the option-then-stored-then-production rule instead.
- **A malformed `DALE_INTEGRATOR_ID` is refused** instead of silently ignored, which used to fall
  through to `/me` and publish under whichever integrator that returned.
- **A declined `dale config set-environment` exits 1**, so a script can tell a switch that happened
  from one that did not; in JSON mode it refuses and names `--force`.
- **`dale list --output json` reports a nested block's `name` as the inner name**, `Inner` rather
  than `Outer+Inner`. `fullName` is untouched — it is the document's identity. Both output modes now
  report the same bindings, where JSON dropped one whose identifier was empty.
- **`dale upload --output json` reports a shape the tool owns** —
  `{status, packageId, version, notices, response}`, with the endpoint's answer nested under
  `response`; the skip shape gains `notices` and keeps `status: "skipped"`. The parser's pack-time
  notices reach both output modes, so which logic blocks the published artifact left out is no
  longer printed only in table mode, which in a release job meant never.
- **Non-ASCII characters survive redirection** — the tool writes UTF-8, so a captured log carries
  `✓`, `✗` and `—` rather than `?` and `-`.

## The DevHost control API

A client of `/api` — the single-page application, an agent, `dale dev`, a smoke skill — sees these:

- **A drive that reaches no block answers `400`** with `reason: unknownHandler` or
  `unknownContract`, where it answered `200` and nothing received the poke.
- **An unknown block or member on a state read answers `404`**, where `200 {}` and
  `200 {"value":null}` were indistinguishable from a block that had published nothing. The
  in-process `GetProperty` / `GetAllProperties` keep their null and empty contract.
- **An unmatched `/api/` route answers `404`**, not the application shell.
- **A write the block never acknowledges answers `400`** with `reason: "unacknowledged"`, where it
  answered `200` once the window elapsed. In process, `SetPropertyAsync` throws
  `ServicePropertyWriteException`.
- **A manual advance that is not a duration a clock can wait answers `400`** — `NaN`, `Infinity` and
  an overflowing value each used to escape as a `500`, and so did a malformed duration anywhere in a
  request body.
- **A second scenario on one stepped generation recycles.** The apply asked whether *this* scenario
  had run before; it asks whether any has, so a bench running several in a row gets the clean slate
  instead of the previous run's leftovers.
- **`GET /api/control/status` gained `blockFailures`** — every handler exception the actor
  middleware caught, per block, as `{ logicBlock, message, error, timestamp }`. A block whose
  configuration, binding or start hook threw used to leave the host reporting itself started with
  its members reading their defaults. It is **every** handler exception, not only the boot's, so on
  a long-lived host a non-empty list means some handler has thrown since this generation started; a
  poller that wants the boot reads it right after the start returns. `IDevHostControl.RecordedFailures`
  is the same list in process.
- **A start no block acknowledges fails instead of hanging**, and under the supervised loop that
  `dale dev` runs a failed boot prints a receipt on standard output —
  `{"failed":true,"port":…,"generation":…,"topology":…,"reason":…}` — rather than surfacing as a
  framework stack trace. A port already in use is named as such. The unsupervised
  `DevHostWebRunner.RunAsync(IDevHost, …)` overload has no such receipt; only its readiness line
  gained `generation`.
- **The readiness line carries `generation` from both entry points.** The unsupervised runner
  printed `{ready, port}` while the supervised loop printed `{ready, port, generation}`, so a parser
  written against one did not read the other.
- **A host supervised by a factory that takes no topology reports `canSwitch: false`** and refuses a
  switch with `409`, where it answered `202` and came back on the topology it was already on.
- **Two conflicts gained a `reason` token** (`notSupervised`, `topologyMismatch`), a clock-mode
  switch is accepted by any supervisor, and `DevHostBuilder.WithSafetyBudgets` makes the host's four
  real-time backstops settable.
- **A topology that is gone, or that no longer builds, no longer takes `dale dev` down.**
- **`DevConfigurationBuilder.ShareContract` is removed.** `PairContracts` is what replaced it, and
  the two are not the same capability — pairing is a wire between two endpoints, sharing was a
  fan-in to one.
- **`ScenarioRunOptions.WriteAcknowledgementWindow` is removed**; the host's own window is the only
  number, so a run can no longer report a refused write as a succeeded step.

## Scenario and topology files

`dale scenario validate` refuses what the runner already refused, so a file your CI accepted may
newly fail: a step carrying a field its kind does not take, and a non-finite, overflowing or
above-49.7-day duration. In the other direction, a topology's instantiation parameters may carry any
value the loader decodes (a `double`, and `null` for a nullable parameter), a name path may be as
deep as the member it addresses, a topology validate call returns more errors at once, and both
schemas refuse `..` without a regex lookahead so an RE2-backed validator stops rejecting the whole
document. A regenerated topology omits an empty `contractMappings`; committed files carrying the
empty array still load unchanged.

## Introspection

- **`packageId` is the nuspec package id**, not the plugin assembly's name. MSBuild defaults one to
  the other, so every current artifact is byte-identical; a library that sets `<AssemblyName>` or
  `<PackageId>` alone now reports the id the platform registers it under.
- **A service property's schema no longer carries `x-kind`.** The measuring-point kind describes the
  series, so it rides the measuring point's schema alone. **If you read `x-kind` off a service
  property, confirm before you take this** — the DevHost's own badge did, and does not now.
- **A component service's members arrive in declaration order**, base class before derived, where
  they used to arrive in binder-insertion order.
- **An array whose elements may be null says so**: `ImmutableArray<string?>` emits
  `items.type: ["string","null"]` where it emitted `"string"`.

## Test kits

- **Every `Times` form is honoured.** `Times.AtMostOnce()` used to crash any verification with
  `ArgumentOutOfRangeException`, and `Times.Between(…)` used to fail a verification whose count was
  inside the range.
- **An analog verification handles the values the wire carries.** A value **equal** to the expected
  one now passes at any tolerance, so `NaN`, `+∞` and `-∞` match themselves where the difference
  comparison rejected them at every tolerance. Equality is `double.Equals`, so `-0.0` still matches
  `0.0`. A non-finite or negative tolerance is refused by name, and `+∞` stays a legal one.
- **A block the construction helper cannot build says why**, and a constructor that throws surfaces
  the author's own exception rather than a `TargetInvocationException` wrapper.
- **The virtual clock keeps its promise when a dispatched action throws** — `AdvanceTime` lands on
  the requested target, and `FlushPendingActions` leaves the remaining actions queued.
- **The Modbus TCP fake refuses what the real client refuses**, the fake synchronous request queue
  refuses a control operation before initialization, and every raise and simulate helper carries the
  kit's logic-block identity instead of an empty one.

## Plugin loading

Isolation wins: a plugin binding to an assembly in its own directory that is **not** marked
`[DaleSharedAssembly]` gets a private copy even when a shared instance with the same simple name
exists. Eager loading over a directory that does not exist completes without loading anything, as
construction already did, and a marked assembly the plugin's context has already loaded is
registered as the shared instance for its simple name.

## Also in this release

`ContentNullAfterDeserializationException` is public and `[PublicApi]`, and the Modbus Core surface
is classified, so both reach the API reference. Every SDK package now builds under the Dale
analyzers. A release that packs `Vion.Dale.Sdk` without its analyzer fails the artifact gate rather
than shipping a package that restores, compiles clean and judges nothing. Timeout and error messages
are rendered in the invariant culture throughout, so a German or Swedish machine no longer prints
`0,05` or a Unicode minus sign into a value another tool parses.
