## At a glance

### Summary

The seventh SDD area pass. `LIFE` is what `LogicBlockBase` guarantees a block author and the runtime
across the message sequence — configure, link, restore, start, run, stop, snapshot, terminate — plus
the `Vion.Dale.ProtoActor` pipeline that carries each message, the persistence and `[Timer]` legs
that ride the sequence, the optional observation seams, and the runtime-vitals core those seams feed
(RFC 0005's SDK half). Phase A produces the behaviour table below; Phase B mints the criteria,
fixes the classified defects, publishes the page and rewrites the area's suites.

### Spec implications

Creates `docs/specs/block-lifecycle.md` (`D1`), `trace: enforced`, area code `LIFE`. It is the page
every other spec page's lifecycle sentence points at: `CTRL` states the host's ordering over it,
`GATE` what a refused configuration does to it, `EMIT` what a value change does inside it, `SCEN`
what stepping does to its delayed sends, `INTRO` what the introspection of a configured block reads.
No existing page changes; the citations already point the right way. Absorbs and deletes
`docs/rfcs/0005-logic-runtime-observability.md`, leaving five files in `docs/rfcs/`, and rewords
`CLAUDE.md:37`'s "six files remain" sentence in the same commit.

### Decisions

- `D1` — the page is `docs/specs/block-lifecycle.md`, titled *The life of a logic block: the message
  sequence, the hooks, and the actor pipeline* — the brief's suggested path, kept: "lifecycle" is
  the word the SDK's own doc comments, the DevHost's teardown code and the architecture repo all
  use, and a reader looking for "what happens between configure and start" will not search for
  "actor".
- `D2` — the spine is the message sequence in the order the runtime sends it (the coordinator's
  recommendation, brief point 3), then the pipeline's per-message contract, then the seams and the
  vitals, then the DI registrations. The three hooks get their own section between start and stop
  rather than being scattered across the sequence, because they are the consumer's contract in prose
  and fifty-three blocks in the first consumer are written against them as a set.
- `D3` — the persistence leg is this page's (brief point 4): no roster area names it and it rides
  the sequence. `GATE` owns what a gate does to it (cited), `ANLZ` owns `DALE007` (cited).
- `D4` — `[Timer]` runtime mechanics are this page's (brief point 5); the analyzer's three
  diagnostics (`DALE002`/`DALE005`/`DALE012`) are `ANLZ`'s and are cited, never re-minted.
- `D5` — the emission-gate bodies that live in `LogicBlockBase.cs` are `EMIT`'s. This page states
  only *where in the life* each runs (built at configuration, force-emitting at start, held while
  running, drained at stop, reset on a republish) and cites `AC-EMIT-001.*` / `AC-EMIT-011.*`.
- `D6` — RFC 0005's SDK half is absorbed here (brief point 2, the coordinator's ratified decision).
  Its runtime-side export wiring (Sink 1's `TagKeys` tiers) and the diagnostics block (Sink 2) are
  consumers — the private runtime's and Tier C's — and are recreated nowhere.
- `D7` — the harness is the brief's (point 6): the block's own sequence runs through

### Error-model overview

The area has four outcomes for a message that cannot be handled cleanly, and which one a caller gets
is the contract:

1. **Refuse and throw** — the configuration message, and only it. A second configuration, an
   unresolvable instantiation parameter, an unusable emission knob, a throw out of a binder or out of
   `Ready()` all leave the handler by exception. The middleware catches it (`ActorMiddleware.cs:67`),
   logs it at error, records it for the host (`AC-CTRL-003.1`) and counts it in the vitals — and the
   actor stays up with a spent instance.
2. **Skip and warn** — a mapping or a link naming an endpoint this instance did not bind
   (`AC-GATE-008.1`/`008.2`), a service identifier with no lookup entry, a persistent entry whose key
   or value the instance cannot take. The block stays whole and the message is partly applied.
3. **Ignore and log** — a value change, a timer tick or a periodic save that arrives while the block
   is not started. Logged at information; nothing is published.
4. **Answer anyway** — restore, stop and snapshot always acknowledge, whatever state the instance is
   in (`AC-GATE-003.5`), because the runtime waits on each of those acknowledgements and a silent
   block hangs its own reclamation.

The defects this pass found are all in one shape: **a fifth outcome that is neither of those four —
a message that is neither applied nor answered nor reported.** Rows 30, 61, 63, 88, 99, 141, 168,
170, 171 are each an instance of it.

## Failure sketches for the ⚠ rows

### `fix` — small, area-local, fixed in Phase B

- **45 — a second start arms a second periodic-save chain.** Start a configured block twice against a
  recording context; count the `PeriodicPersistentDataSaveMessage` self-sends. Two chains, both
  self-rescheduling, and only a stop retires either. *Fix:* return early from the start arm when the
  block is already started.
- **53 — the stop hook's symmetry rule names a cancellation the dispatcher does not have.** Schedule a
  delayed action, stop the block, deliver the action: it runs. The doc says such a thing "should
  typically be … cancelled here" and offers no way. *Fix:* the doc comment, under
  `sdk-surface-conventions.md` § 2 — the code is right.
- **54 — either dispatcher member before the first message throws a bare null-reference.** Construct a
  block, call `InvokeSynchronized`, observe `NullReferenceException` with no message. *Fix:* a guard
  throwing `InvalidOperationException` naming `Ready()`/`Starting()` as the place to schedule from.
- **55, 56 — a delayed action at a negative or over-long delay is lost silently.** The throw leaves the
  handler and the middleware swallows it, so the block loses the reschedule that keeps its cycle
  alive. *Fix:* clamp a negative delay to zero (the treatment `ScheduleEmissionFlush` already gives a
  past deadline) and refuse a delay above the bound `AC-SCEN-003.2` already names, with a message
  naming the member.
- **108 — a second stop runs the stop hook twice.** Stop a started block twice; the hook runs twice and
  the second run's writes are dropped because the started flag is already false. *Fix:* return early
  from the stop arm when the block is not started, keeping the acknowledgement (`AC-GATE-003.5`).
- **230 — the no-sender guard's exception message is malformed.** *Fix:* rewrite the string to name
  the member and the cause; no behaviour moves.
- **234 — the plugin hook's doc gives lifetime advice for the block type that nothing reads.** Register
  a block as a singleton and spawn two actors of it: two instances. *Fix:* the doc comment, under
  `sdk-surface-conventions.md` § 2 — say that the registration makes the block discoverable, that a
  block is constructed per actor whatever its lifetime, and that the lifetime that does matter is its
  dependencies'.
- **222, 223 — a non-finite or over-long `[Timer]` interval fails the configuration with a
  duration-conversion message.** Declare `[Timer(double.NaN)]` and configure the block: the
  configuration throws `ArgumentException` from `TimeSpan.FromSeconds`, naming neither the method nor
  the block. *Fix:* validate the interval in the binder's own loop, next to the signature check,
  reusing that check's message shape (method, declaring type, the value read).
- **198 — a zero vitals window blanks four of the eleven vitals.** Build the core with a zero window,
  record a handled message, read the snapshot: the cumulative total is there and every windowed
  maximum is the type's default. *Fix:* refuse a non-positive window at the constructor.

### `park` — recorded in the ledger, not fixed here

- **5 — two published message types nothing in this repository sends or receives.** The private
  runtime's remote-interface proxy handler is the only reader, so no in-repo test can pin them.
- **26 — a contract handler reference is minted whether or not the actor exists.** A fix is a registry
  lookup at link time, which turns a spawn-ordering assumption into a contract shared with the
  private runtime — too far-reaching for this pass.
- **89 — a `[Persistent]` property deeper than one level is silently not persisted.** Recursing needs a
  cycle guard, a key grammar for arbitrary depth and a decision about collections: its own change doc.
- **137 — the actor name is ambiguous when a block's name or id contains the separator.** No reader in
  the repo splits it, so there is no harm to name today.
- **208 — the SDK ships an OTel meter type no in-repo host wires.** Registering it in `AddDaleSdk`
  would start a meter in the DevHost, the TestKit and every example.
- **216 — the two dependency-injection registrations are independent and one host uses only one.**
  Whether *actor system without the SDK's registrations* is a supported composition is the operator's
  call, not a defect.
- **227 — a published `IActorContext` member nothing in the repository reads.** Removing it is a
  surface decision, not a pass's.
- **217 — a shipped package and three namespaces outside the public-API snapshot.** The same gap
  `CTRL`'s row 201 recorded; a surface decision, not a pass's.

### `propose` — a wire or semantics change; recommendation on the row, decision the operator's

- **10 — a contract message to an unbound contract throws where its interface twin skips.**
  *Recommendation:* guard the contract lookup the way `:336-352` guards the interface one, and let
  `AC-GATE-008.3` cover both directions.
- **30 — a bound service missing from the configuration's identifier lookup is dropped at six sites
  for the instance's life.** *Recommendation:* fail the configuration instead of warning six times.
- **33 — a linked-interface map arriving before the configuration is dropped for good.**

- **47 — a block whose configuration failed still starts and acknowledges.** *Recommendation:* refuse

- **61 — two `[Timer]` methods sharing an identifier: one is discarded, the other double-ticks.**

- **63, 88 — a `[Timer]` or `[Persistent]` declared private on a base class is silently unbound.**

- **64 — an empty `[Timer]` identifier is accepted and reaches the vitals as a tag.**
  *Recommendation:* refuse an empty or whitespace identifier at the binder.
- **68 — a timer chain keeps ticking between the stop and termination.** *Recommendation:* reschedule

- **99 — a set-value request for an unknown service is never answered.** *Recommendation:* answer with

- **103 — a stop-hook exception reaches only the log.** *Recommendation:* record it the way the

- **170, 172 — a duplicate acknowledgement or termination satisfies the count for a silent actor.**

- **224 — a sub-tick `[Timer]` interval arms a zero-delay tick chain.** *Recommendation:* refuse
  an interval that converts to a zero duration at the binder, with the same message as rows 222–223.

  *Recommendation:* state the combining rule; the reachability question rides row 216.
- **214 — the actor-system registration registers no clock.** *Recommendation:* have it call the SDK's

## Relay notes for the PR body

Every behaviour this pass moves, in the words a consumer needs. A block author, the private runtime's
initializer and any host driving `LogicBlockBase` directly read this list.

- **A configuration now refuses a `[Timer]` it cannot schedule, naming the method.** Six declarations
  that used to be accepted are refused at start: two timers sharing an identifier (only one ever ran,
  and it ran on both intervals), an empty or whitespace identifier, an interval that is not a number,
  an infinite one, one longer than a real clock can wait, and one shorter than a single clock tick —
  which armed a tick chain at no delay at all. **A block that shipped past a suppressed `DALE012` now
  fails its configuration.** *(rows 61, 64, 222–224.)*
- **A `[Timer]` or `[Persistent]` declared private on a base class is now bound.** Both discovery walks
  missed a base class's private members, so a base class of blocks that scheduled its own cycle never
  ticked and one that kept private state lost it on every restart — silently, at every door. Both now
  walk the base chain. Two consequences worth knowing: a base and a derived timer that share a method
  name are now the duplicate identifier above and are refused, and a previously inert private
  `[Persistent]` on a base class starts appearing in the persisted file. Checked against the first
  consumer: every `[Timer]` there is a public method on a concrete block and every `[Persistent]` is
  public, so no fielded block has such a member. *(rows 63, 88.)*
- **A negative acknowledgement or termination timeout is refused where it used to hang.**
  `SendAndWaitForAcknowledgementAsync` and `StopActorsAndWaitAsync` armed their timeout with a delay
  the framework refuses, inside a temporary actor with no middleware — so the actor restarted in a loop
  and the caller's `await` never returned at all. Both now throw `ArgumentOutOfRangeException` before
  anything is sent or watched. A timeout of zero is unchanged: an immediate `TimeoutException`.
  *(rows 168, 171.)*
- **Both waits now count distinct actors.** A second acknowledgement from one actor, or one from an
  actor that was never asked, used to satisfy a silent actor's share — so a wait could complete while a
  block that never answered was still silent, which is exactly the failure a lifecycle wait exists to
  catch. The termination wait had the same shape. *(rows 170, 172.)*
- **A stop-hook exception now reaches the host's health surface, after the acknowledgement.** It used
  to be logged and swallowed inside the block, where `AC-CTRL-003.1`'s per-block failure list could not
  see it. The stop still finishes and still acknowledges first; the failure is reported afterwards.
  **A harness that drives `StopLogicBlockRequest` directly now sees a throwing stop hook propagate** —
  one such test existed in `Vion.Dale.Sdk.TestKit.Test` and now consumes it. *(row 103.)*
- **A contract message to an unbound contract is skipped with a warning where it threw.** The contract
  arm indexed its map where the interface arm beside it guards; a deliberately dead wire therefore
  recorded a handler exception and counted a vitals error. `AC-GATE-008.3` now states the rule for both
  directions. *(row 10.)*
- **A linked-interface map that arrives before the configuration is applied instead of dropped.** It
  used to be warned away mapping by mapping and lost for the instance's life, leaving the block running
  unlinked. It is now held and applied at the configuration's tail, after the ready hook — which is
  where the hook contract says a block may read its links. Both in-repo hosts and the runtime send it
  after the configuration, so nothing observable moves for them. *(row 33.)*
- **A second start or a second stop is acknowledged and does nothing.** A second start used to run the
  hook again, republish every value and arm a second periodic-save chain that only a stop retired, so a
  block started twice wrote its snapshot twice a minute for the life of the process. A second stop used
  to run the hook again with the started flag already down. Both still acknowledge, because the runtime
  waits on the answer. A **first** stop on a block that never started is unchanged and still runs the
  hook — the guard keys on having stopped, not on having started. *(rows 45, 108.)*
- **A delayed action's negative delay is clamped to nothing and an over-long one is refused.** Both used
  to throw out of the handler, where the middleware swallowed it — so a block silently lost the
  reschedule that kept its cycle alive. The bound is the one a scenario's durations already carry.
  *(rows 55, 56.)*
- **Either dispatcher member called before the block's first message now refuses, naming the hooks.** It
  used to be a bare null-reference exception through the middleware. *(row 54.)*
- **A vitals window of nothing or less is refused.** It reported all four windowed maxima as nothing
  while the counts beside them rose. *(row 198.)*
- **Five doc comments and one exception message corrected**, with no behaviour change: the stop hook's
  symmetry rule (a scheduled action cannot be cancelled and still runs after the stop), the start
  hook's persisted-value promise (true on a host that restores; the development host restores nothing),
  `LogicBlockBase`'s own remark that a block implementing a disposal interface is never disposed, the
  plugin hook's lifetime advice (a block's own registration lifetime is not consulted — its
  dependencies' is), `AddProtoActorSystem`'s remark on what it takes from the container and why it is
  called once, and the no-sender refusal's malformed text. *(rows 53, 124, 154, 234, 214, 230.)*
