## At a glance

### Summary

The eighth SDD area pass. `BIND` is how a logic block declares, binds and exchanges messages over
its two endpoint families — the **inter-block interface** (a `[LogicBlockContract]` class, the
`[LogicInterface]` triple the generator emits for it, the `[LogicBlockInterfaceBinding]`, the
interface binder and factory, the sender base and the generated sender surface) and the
**service-provider contract** (`[ServiceProviderContractType]`, `[ServiceProviderContractBinding]`,
the contract binder and factory, `LogicBlockContractBase`) — plus the **provider face** on the far
side of the second: `ServiceProviderHandlerBase`, its MQTT registration, its publish and forward
helpers, and the marker that keeps a development-only face off a production host. Phase A produces
the behaviour table below; Phase B mints the criteria, fixes the classified defects, publishes the
page and writes the area's suites, which today do not exist for anything but the four attributes.

### Spec implications

Creates `docs/specs/contracts.md` (`D1`), `trace: enforced`, area code `BIND`. It is the page every
other spec page's *endpoint* sentence points at: `INTRO` states what an endpoint's identity and
document entry are, `GATE` what an inclusion gate does to a binding, `LIFE` when the binders run and
what a routed message does when the endpoint is absent, `SCEN` how a scenario drives a contract and
`CTRL` what the development host stands in with. No existing page changes: every rule this page
would otherwise restate is already stated by one of those five and is cited. Absorbs and deletes
no RFC — the five remaining files are `TKIT`'s (`0001`, `0002`), `MODB`'s (`0007`, `0018`) and
`CLI`'s (`0009`), so `CLAUDE.md:37`'s "five files remain" sentence stands unchanged.

### Decisions

- `D1` — the page is `docs/specs/contracts.md`, titled *Contracts and provider faces: declaring an
  endpoint, binding it, and exchanging messages*. The brief's suggested path, kept: "contract" is
  the word `docs/spec-process.md:7` uses for this SDK's unit of specification, the word both binding
  attributes carry, and the word an author searching for "how do two blocks talk" will type. The
  alternative, `wiring.md`, would have matched `architecture/concepts/logic-block-wiring.md` — but
  that concept is about *multiplicity*, which this page only declares.
- `D2` — the spine is the coordinator's recommendation (brief point 2): the two families each in the
  order an author meets them (declare the contract → bind an endpoint → get linked → exchange), then
  the provider face (implement → register → receive → forward → publish), then the discovery rules
  the two factories share and where they diverge, then the identities. The attributes are not a
  section of their own: each is stated where its reader walks it, because an attribute nothing reads
  is exactly the defect this pass found twice.
- `D3` — the **generator's emitted surface is this page's** (brief point 3); the generator's
  diagnostics and the analyzer registry are `ANLZ`'s and are cited (`DALE001`, `DALE009`–`DALE011`,
  `DALE019`, `DALE020`, `DALE025`, `DALE043`, `DALE045`). The emitted surface is stated from the
  template and proven on the generated files the test project already compiles, because the
  conventions the factory instantiates by — the five-argument constructor, the `SenderInterface`
  suffix, the `<Type>Extensions.RegisterInstance` lookup — are a contract between two halves of the
  SDK that a consumer's rebuild silently depends on.
- `D4` — the handler-actor protocol is stated as *what the SDK gives a provider-face author* (brief
  point 4): the records, the `/+/+/+` subscription prefix, the publish conventions, the contract-id
  parse. The MQTT client's own behaviour — the registration aborts `RegisterMqttHandler`'s remarks
  describe, the installation prefixing, delivery — is the private runtime's, is carried on the
  published surface and is specified nowhere. `RegistrationSecret` is the gateway's registration and
  belongs to no roster area: a checkpoint and one ledger line (`DC-6`, row 199).
- `D5` — `LinkMultiplicity` and `Consumers` are stated as *declared by the SDK and enforced
  downstream* (brief point 10, decision `0021`). No criterion is minted for an enforcement nobody
  wrote; what is minted is the vocabulary, the defaults, and the fact that the default is omitted
  from the annotations rather than emitted.
- `D6` — the harness is the brief's (point 7): the block side runs through `HandleMessageAsync`
  against `TestHelpers/LifecycleHarness.cs`'s recording context, which records every send with the
  target's name; the handler side is a `ServiceProviderHandlerBase` subclass driven through the same
  `HandleMessageAsync` with the same context. No project reference from `Vion.Dale.Sdk.Test` to the
  TestKit or to the I/O families; no real MQTT. New fixtures are declared in `TestHelpers/`, never in
  another area's suite file.
- `D7` — the two dead `CodeGeneration` attributes (brief point 5) are split: the five private binder
  methods that read one of them are a `fix` (delete), and the attributes themselves are a ledger line
  rather than a row, because removing a public attribute that fourteen shipped declarations carry is
  a public-surface removal, not a pass-sized cleanup. The brief's count is corrected in `DC-2`.

### The error model of a binding

A declaration that cannot be honoured has exactly five ends in this area, and which one an author
gets is the contract they are owed:

1. **Refused at compile time** — `DALE001`, `DALE009`–`DALE011` are `DiagnosticSeverity.Error`, so
   the three shapes they cover never reach a running block from a compiled assembly.
2. **Refused at bind time** — a missing setter, a blank identifier, a collision, an unresolvable
   sender implementation. The configuration message throws; `LIFE` records the reason and the actor
   stays up with a spent instance (`AC-GATE-004.1`).
3. **Skipped with a warning** — a mapping or a link naming an endpoint this instance did not bind
   (`AC-GATE-008.1`–`008.3`), a send to an unlinked interface id.
4. **Dropped in silence** — a contract with no mapping, a state update with no links, a forward for
   an unmapped contract id. Each is documented design.
5. **Never noticed at all** — a binding attribute whose type carries no marker, a `ForInterface` the
   member does not implement, a non-public interface-bearing property, a message attribute outside
   its contract class, two attributes nothing reads. **This fifth outcome is where every `propose`
   row in sections A and B sits**: the author wrote a declaration, the compiler accepted it, no
   diagnostic fired, and the endpoint does not exist.
