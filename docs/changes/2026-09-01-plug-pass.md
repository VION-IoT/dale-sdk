# PLUG area pass — the plugin loading ABI

> Change doc — one in-flight change. The `Spec delta` below is distilled into the current-truth
> pages under `docs/specs/` in the implementation PR, then this doc is archived
> (`pwsh scripts/spec-change.ps1 archive plug-pass`). Process: `docs/spec-process.md`. Never put
> change narrative inline in a spec page — it lives here.

## At a glance

### Summary

First SDD area pass (pilot). Turns the plugin loading ABI — `PluginLoadContext`'s four resolution
strategies, the `[DaleSharedAssembly]` sharing rule, and the SDK major-version gate — into a
current-truth spec page with an id-cited test suite. The area pilots because its coverage is one
test class over one seam: 8 tests, all on the version gate, **none on `Load()`** — the resolution
rules that actually define the ABI are entirely untested.

### Spec implications

Creates `docs/specs/plugin-loading.md` (new, Tier A, `trace: enforced`) carrying `AC-PLUG-*`
criteria for: context construction and the version gate; the shared-name set derived from the
host SDK's references (strategy 1); framework-assembly resolution (strategy 2); the
`[DaleSharedAssembly]` shared-extension cache (strategy 3); plugin-private isolation as the
default (strategy 4); and the eager-load / shared-registry surface the LogicBlockParser consumes.
No existing page changes; `_invariants.md` gains nothing this pass (no cross-cutting rule emerged
that a second area would also cite).

### Decisions

- `D1` — The area's anchor is **not** the PublicApi manifest. `Vion.Dale.Plugin` and
  `DaleSharedAssemblyAttribute` are absent from `docs/snapshots/publicapi-manifest.json` by design
  (zero `[PublicApi]` types; the attribute is `[InternalApi]`) — already stated in
  `docs/sdk-surface-conventions.md:216`. The anchors used instead are the `[DaleSharedAssembly]`
  usage set (4 assemblies, grep-enumerable), the `GetSharedAssemblyNames` derivation, and the
  `PluginSdkVersionMismatchException` surface. See the Drift checkpoint.
- `D2` — Rows covering the **private** resolution helpers (`ShouldLoadFromDefaultContext`,
  `HasDaleSharedAssemblyAttribute`, `GetSharedAssemblyNames`) are stated as behaviors of `Load()`,
  not of the helpers, because that is the observable seam. Their tests will drive `Load()` through
  a real ALC over fixture assemblies rather than reaching the private methods by reflection
  (`testing-conventions.md` §7).
- `D3` — `Vion.Dale.Sdk.Modbus.Core.Test/SharedAssemblyMarkerShould.cs` tests a PLUG anchor from
  the MODB project. It is mapped, not rewritten: it lives in another area's project and that
  area's pass has not run.

**Failure sketches (⚠ rows).**

- **30** — `new PluginLoadContext(@"C:\does-not-exist", "Acme.Plugin", logger)` returns normally
  (row 5); the very next line, `context.EagerlyLoadSharedExtensions()`, throws
  `DirectoryNotFoundException` out of `Directory.EnumerateFiles`. A host that treats successful
  construction as "this path is usable" crashes on the second call instead of the first.
- **31** — `LogicBlockParser` loads `Acme.Shared.dll` by path (`Program.cs:259`), then calls
  `EagerlyLoadSharedExtensions()`. That method sees the name is not in `SharedExtensionAssemblies`,
  calls `LoadFromAssemblyName("Acme.Shared")` — which returns the already-loaded instance **without
  invoking `Load()`** (verified this session with a recording `AssemblyLoadContext` subclass: load
  by path, then `LoadFromAssemblyName` on the same simple name → same instance, `Load()` call count
  0). `SharedExtensionAssemblies` is written only inside `Load()` (`:188`), so the assembly is never
  registered and `Program.cs:298` skips its `IConfigureServices`.
- **32** — Plugin A ships `Acme.Shared.dll` marked `[DaleSharedAssembly]`; it is loaded and cached.
  Plugin B ships its own, differently-built, **unmarked** `Acme.Shared.dll`. Plugin B binds to it,
  `File.Exists` passes at `:157`, the cache hit at `:160` returns plugin A's assembly, and plugin B
  silently runs against code it did not ship. The attribute check at `:169` is never reached.

## Spec delta (to distill)

- ADDED AC-PLUG-002.1 -> docs/specs/plugin-loading.md : WHEN a plugin load context is created over a directory containing an assembly built against a Vion.Dale.Sdk whose major version differs from the SDK the host has loaded, THE SYSTEM SHALL reject the plugin with a PluginSdkVersionMismatchException before loading any plugin assembly into the context.
- ADDED AC-PLUG-002.2 -> docs/specs/plugin-loading.md : WHILE the host and plugin Vion.Dale.Sdk major versions are equal, THE SYSTEM SHALL create the context whatever the minor and patch versions are.
- ADDED AC-PLUG-002.3 -> docs/specs/plugin-loading.md : WHEN the version gate rejects a plugin THE SYSTEM SHALL name the package id, both Vion.Dale.Sdk versions and the rebuild remedy in the exception message, and record the rejection at error level.
- ADDED AC-PLUG-002.4 -> docs/specs/plugin-loading.md : WHEN the plugin directory does not exist THE SYSTEM SHALL create the context without inspecting any assembly.
