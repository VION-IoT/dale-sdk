## At a glance

### Summary

The thirteenth SDD area pass: the five packable test kits — the core kit, the two I/O kits and the
two Modbus kits — become one current-truth spec page, `docs/specs/testkit.md`, with an id-cited test
suite across their five MSTest projects. This is the pass that empties `docs/rfcs/`: RFC 0001
(virtual time, Implemented) and RFC 0002 (handler test kit, Draft) are absorbed and deleted, and the
directory goes with them.

### Spec implications

Creates `docs/specs/testkit.md` (`trace: enforced`), the area's first page. It states what a block
author calls, what each helper refuses and with which exception and message, what every default is
(`Times.Once()`, tolerance `0`, the `2026-01-01T00:00:00Z` anchor, `EmissionPolicyMode.Off`,
`TimeProvider.System` on the TCP harnesses), what the builder's five phases do, what `AdvanceTime`
and `FlushPendingActions` each drive, and what the two Modbus fakes stand in for.

Cited, never re-minted: `block-lifecycle.md` (the five phases the builder drives), `emission.md`
(`AC-EMIT-001.3/.4` — the policy override), `config-gating.md` (`AC-GATE-012.1`),
`contracts.md`/decision `0081` (the binder rules the kit diverges from), `modbus.md` (the client and
queue the fakes stand in for), `io.md` (the four faces). `scenarios.md:20`'s unnamed deferral — "the
TestKit's virtual time and block lifecycle are other pages'" — resolves to this page.

Touches `docs/testing-conventions.md` § 7 (a stale sentence, corrected in-pass),
`docs/spec-process.md` and `CLAUDE.md` (the `docs/rfcs/` sweep).

### Decisions

- `D1` — **Page name `docs/specs/testkit.md`, area code `TKIT`.** One page for five packages: they
  ship as one contract (four of the five exist only to extend the core kit's
  `LogicBlockTestContext<T>`), and a page per package would state the same builder five times.
  The roster (`docs/spec-process.md:35`) reserves `TKIT` for "TestKit surfaces (virtual time)"; the
  page is wider than virtual time and the code is unchanged.
- `D2` — **Spine:** construction and lifecycle → the recording context and the verify family → the
  raise helpers → time → the two Modbus kits → the surface → the test discipline. That is the order
  an author meets the machinery, and it is the coordinator's recommendation in the brief (point 2),
  adopted unchanged.
- `D3` — **The harness is the five existing MSTest projects; no new project.** The kit is the SUT,
  driven through a fixture block (`SampleLogicBlock` / `SampleProviderLogicBlock` — the ideal-echo
  recipe of `docs/simulator-authoring.md`), never through a runtime, a broker, a device or the
  DevHost. The three uncited projects (Digital, Analog, Rtu) are rewritten to
  `docs/testing-conventions.md` § 9–17 where a rewrite is needed to cite.
- `D4` — **A change reaching a signature, a default, an exception type, a message shape or a package
  reference is a `propose` row, not a `fix`** — the kits are published packages with 126 consumer
  `.cs` files in `logic-block-libraries` alone. A fix *inside* a helper that leaves every existing
  assertion's outcome unchanged is a `fix` (brief point 4), and every such row below names the
  reader search that proved no consumer depends on today's behaviour.
- `D5` — **RFC 0002 is absorbed as a park, not implemented.** A handler test kit is a new
  `[PublicApi]` type family — a change doc's worth of work, and outside a pass's size guard. The
  page states what the kits do *not* offer and why the SDK's own handler suites roll their own; the
  ledger carries the design. This is the one question whose answer changes the pass's size, and it
  is Reviewer's question 7 below.
