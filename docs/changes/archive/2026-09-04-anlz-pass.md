# ANLZ area pass — the DALE diagnostic registry and the analyzers that report it

> Change doc — one in-flight change. The `Spec delta` below is distilled into the current-truth
> pages under `docs/specs/` in the implementation PR, then this doc is archived
> (`pwsh scripts/spec-change.ps1 archive <slug>`). Process: `docs/spec-process.md`. Never put
> change narrative inline in a spec page — it lives here.

## At a glance

### Summary

The ninth SDD area pass. Covers the `DALE` diagnostic registry shipped inside `Vion.Dale.Sdk`'s
package as `analyzers/dotnet/cs`, the thirty-six analyzers that report it, the shared symbol walk
they rest on, the severities and tags, the source generator's own untagged diagnostics, the
packaging that puts the pack into a consumer's build, and the whole
`Vion.Dale.Sdk.Generators.Test` suite — which this pass brings under
`scripts/test-style-lint.ps1` by retiring its exemption.

### Spec implications

Creates `docs/specs/analyzers.md` (`trace: enforced`), area code `ANLZ`. The page states the
registry as a contract (ids, one category, severities, tags, retirement, enabled by default), what
every analyzer can and cannot see, the diagnostics by family with the ids as the `[DataRow]`s of
their tests, the packaging and the wiring probe, and points at
`docs/testing-conventions.md` § 3 and `docs/sdk-surface-conventions.md` §§ 4–5 for the author
disciplines rather than restating them.

Rows the neighbouring pages already own are **cited, never re-minted**: `AC-GATE-011.1`–`011.11`
(the `[IncludedWhen]` / `[InstantiationParameter]` authoring diagnostics), `AC-EMIT-012.1`–`012.7`
(the emission knobs), `AC-LIFE-007.2` (the timer binder's refusals), `AC-INTRO-017.4` (the wiring
probe), `AC-INTRO-014.3`/`014.4` (endpoint identifiers), the `BIND` criteria naming a `DALE` id,
and `AC-SCEN-*` for `DALE046`.

### Decisions

- `D1` — Page path `docs/specs/analyzers.md`, title *"Analyzer diagnostics: what the SDK refuses at
  compile time"* — the flat one-noun page name the corpus already uses (`emission.md`,
  `introspection.md`), and the subject is the registry, not the analyzer classes.
- `D2` — Spine: the registry as a contract → what every analyzer sees → the diagnostics by family
  (contract and message shapes; timers; supported types; presentation hints; access flags; emission
  knobs; observability; public-API documentation; gating and instantiation; scenario wire) → the
  packaging and the wiring probe → a pointer to the test discipline. Ids are the `[DataRow]`s of a
  family's criterion, never one criterion per id.
- `D3` — The generator's three `SourceGenerator`-category pseudo-diagnostics
  (`LogicClassGeneratorDBG`/`INF`/`ERR`) are this page's to state as what they are: outside the
  registry, untagged, absent when the generator does not run. `LogicClassGeneratorDBG` has no call
  site at all and is deleted in this pass (row 148); whether `…ERR` deserves a registry id is
  question 3.
- `D4` — The harness stays `AnalyzerTestBase` + `TestAttributeStubs.cs`; no snapshot files; the
  wiring probe is not extended, and its build-shape hazard is stated rather than re-guarded
  (journal `:134`, `AnalyzerWiringShould.LeaveBuildOutputsOfDependencyGraphUntouched` is the
  standing guard).
- `D5` — `scripts/test-style-lint.ps1`'s `Vion.Dale.Sdk.Generators.Test/` exemption
  (`:53-54`) retires in Phase B; all 358 tests conform afterwards. **Ordered: citations first, then
  names.** The gate skips any method with no `AC-`/`SYS-` literal in its attribute block (`:70`), so
  retiring the exemption before the citations land would gate 93 of 358 and read as green.
- `D6` — Retired ids (`DALE006`, `DALE029`) stay retired; every new diagnostic this pass mints takes
  the next free id from `DALE047`. A new **Error**-severity firing shape is `propose`, never `fix`,
  because the first consumer suppresses nothing (verified: 0 `#pragma`, 0 `NoWarn`, 0 `.editorconfig`
  line naming a `DALE` id, no `TreatWarningsAsErrors` in either repository).
  **Overridden once, at the classification, on searched evidence:** `DALE048` (row 174) ships at
  `Error` because the shape it fires on — a blank `[ServiceProviderContractType]` token — was
  searched for in the consumer's eight tokens and in every analyzer-judged in-repo project and does
  not occur. `DALE047` (row 47) keeps the policy and ships at `Warning`. The rule stands for every
  future id; the override is the operator's to confirm.
- `D7` — `VisibleWhenPredicateAnalyzer` carries private copies of seven `AnalyzerHelper` members
  with identical bodies (`:221-369`). No observable differs today, so the row is `out-of-spec`; the
  duplication is named on the page as a drift hazard and collapsed only if the operator asks.
