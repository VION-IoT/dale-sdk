# MODB area pass — the Modbus protocol bindings

> Change doc — one in-flight change. The `Spec delta` below is distilled into the current-truth
> pages under `docs/specs/` in the implementation PR, then this doc is archived
> (`pwsh scripts/spec-change.ps1 archive <slug>`). Process: `docs/spec-process.md`. Never put

## At a glance

### Summary

The tenth SDD area pass turns `Vion.Dale.Sdk.Modbus.Core`, `.Tcp` and `.Rtu` — 86 source files, 73
public types, 30 `[PublicApi]` marks, 388 tests in 25 files, none citing a criterion — into one
current-truth spec page. It absorbs and deletes RFC 0007 (Modbus-TCP server) and RFC 0018 (per-block
socket lifetime), leaving three files in `docs/rfcs/`. What a logic-block author gets from a Modbus
binding — the 36 reads and writes, the receipt, the link policy, the queue, the conversion, the
hosted server, the RTU contract, the diagnostics — is stated once, with the code as evidence.

### Spec implications

Creates **`docs/specs/modbus.md`** (`D1`), `trace: enforced`, minting `AC-MODB-*`. Nothing else in
`docs/specs/` changes except `_findings.md`, which gains a `## MODB` section for the `park` rows.

Rows another page owns are **cited, never re-minted**: the generic `[ServiceProviderContractBinding]`
and `ServiceProviderHandlerBase`'s arms (`AC-BIND-*`), `[assembly: DaleSharedAssembly]` loading
(`AC-PLUG-*`), the emission of the diagnostics as service properties (`AC-EMIT-*`), the stop hook's
promise (`AC-LIFE-012.*`), the DevHost's stand-ins (`AC-SCEN-*`, `AC-CTRL-*`), the analyzer pack's
reach (`AC-ANLZ-018.2`), and architecture decisions `0118` / `0119` / `0014` / `0023` / `0037`–`0039`
/ `0139` by number.

Outside `docs/specs/`: `CLAUDE.md:37`'s "five files remain" becomes three (`0001`, `0002`, `0009`);
`.claude/skills/modbus-smoke/SKILL.md:12-13` carries a claim this pass disproves (row 165).

### Decisions

- `D1` — the page is **`docs/specs/modbus.md`**, the brief's suggested path. "Modbus" is the
  published vocabulary a consumer greps for; `modbus-bindings` would name the folder layout instead.
- `D2` — the spine is the coordinator's recommendation verbatim (Reviewer's question 2): client
  surface · link policy · queue · conversion · server · RTU · diagnostics · DI and socket lifetime ·
  test discipline. It orders the page the way a block author meets the surface.
- `D3` — **both RFCs are absorbed and deleted this pass.** Every implemented clause becomes a
  criterion with the code as evidence; every deferred or open item becomes a ledger line with an
  owner. `docs/rfcs/README.md` names neither, so the sweep is `CLAUDE.md:37` plus the two files'
  own cross-references.
- `D4` — the harness the rewritten suite moves to: a **fake at the proxy seam**
  (`IModbusTcpClientProxy`) plus `SynchronousRequestQueue` where the criterion is about the link
  policy or the queue; Moq stays only where the collaborator genuinely has no state
  (`IActorDispatcher`, `IModbusRtuRequestFactory`'s callers). The three real-socket suites keep
  their sockets, are serialised against each other, and never run beside the smoke skill.
- `D5` — **the diagnostics the SDK owns are this page's** (decision `0118`): what each field of
  `ModbusLinkSummary` and `ModbusTcpConnectionSummary` records and when it moves. Their *emission*
  as `[ServiceProperty]` is `EMIT`'s and is cited.
- `D6` — **no analyzer judges these three projects.** None carries the analyzer `ProjectReference`
  that `Vion.Dale.Sdk.DigitalIo` and `.AnalogIo` do, so `AC-ANLZ-018.2` puts every declaration here
  outside the pack. The page states it; nothing is minted for an enforcement that does not exist.
- `D7` — the brief's phrase *"`ANLZ`'s Known non-conforming code"* names no section of
  `docs/specs/analyzers.md`. The citation used instead is **`AC-ANLZ-018.2`**, which states the rule
  the brief was reaching for. (Drift checkpoint.)

### The reader reads that changed a row's class

Two claims the extraction would have got wrong from the SDK alone, both settled by opening the
reader:

- **Rows 150 and 151.** RFC 0018 § 8.3's leak is real at the SDK

## Failure sketches for the ⚠ rows

**Row 15 — `Invalid` and `Cancelled` are documented as counted and are not.**
A block reads `Link.ExpiredCount + Link.DroppedCount + Link.BackedOffCount` to see how much local
shedding is happening, believing the docs' "local outcomes … are still counted"; every request
refused for a bad unit id or lost to a disposal is invisible in every counter, so a
misconfigured unit id looks like a client doing nothing at all.
*Fix:* either add `InvalidCount` and `CancelledCount` to the summary and the accumulator, or correct
the two sentences to name the five outcomes that do have counters. The second is not source-breaking
and is the smaller claim; the first changes an 18-field published struct.

**Row 17 — `quantity` and `count` name the same argument position.**
A block author copies a working `ReadHoldingRegistersAsUShort(unit, addr, quantity: 4, …)` into a
32-bit read and the compiler rejects `quantity:`; worse, they pass 4 to `count` meaning registers and
silently read eight.
*Recommendation:* leave both names. The distinction is real — one counts registers, the other values
— and renaming either breaks every named-argument call site in the first consumer's 84 files. State
it on the page instead, per family.

**Rows 25 / 112 — port 0 is accepted on both the client and the server.**
A commissioning form leaves the port empty, the binder writes 0, and the client spends its life
arming backoffs against a port that cannot answer, while the server binds an ephemeral port and
reports `IsListening == true` on a number no one was told. The first consumer's own
`ModbusConnection` already declares `Minimum = 1` (`…/Shared/ModbusConnection.cs:46`), so the
consumer refuses what the SDK admits.
*(park)* One boundary per setter, but the client's and the server's are the same question and the
server's `Port` doc explicitly says "0-65535" — a ledger entry that decides both at once, with the
doc, is worth more than two independent one-line fixes.

**Row 41 — the connect-timeout message is culture-formatted.**
A gateway running under a comma-decimal culture reports *"The connection could not be established
within 2,5 seconds."*; a test that pins the message passes on the author's machine and fails on CI's
Linux runner — the exact shape that failed one test of 455 in the ANLZ pass.
*Fix:* `string.Format(CultureInfo.InvariantCulture, …)`, matching the area's three other message
builders.

**Row 44 — the classifier's default faults the link for a local failure.**
A block sets `DefaultOperationTimeout` from a commissioning field to `-5 s`; every operation throws
`ArgumentOutOfRangeException` from the timeout CTS, classifies as `TransportError`, closes the socket
and reports the device `Faulted` — the operator replaces a working device.
*Recommendation:* keep the default (an unrecognised exception genuinely might be transport) but
classify `ObjectDisposedException` as `Cancelled` and `ArgumentException`/`ArgumentOutOfRangeException`
as `Invalid`. It is a reclassification a block's error callback can see, so it is the operator's call.

**Row 47 — two unguarded timeout knobs beside three guarded ones.**
`ConnectionTimeout = TimeSpan.Zero` makes `Task.Delay(0)` win every race in
`ModbusTcpClientProxy.ConnectAsync`, so every connect raises `ConnectionTimeoutException`, two in a
row arm a backoff, and the client never reaches a device that is present and answering.
*Fix:* refuse `<= 0` on both setters with `ArgumentOutOfRangeException`, exactly as `ConnectBackoff`
and `MaxQueuedAge` already do.

**Row 48 — one proxy seam, two unit-identifier types.**
A second `IModbusTcpClientProxy` implementation (a bench, a recording proxy) has to write four
`int` overloads and four `byte` ones for one protocol field, and a `(byte)` cast in the wrapper turns
unit id 256 into 0 rather than reaching the validator — which cannot happen today only because
`ValidateUnitIdentifier` runs first.
*Recommendation:* unify on `int`. It is source-breaking for any implementer outside this repository;
inside it, only `FakeModbusTcpClientProxy` and `ModbusTcpClientProxy` implement it.

**Row 52 — a public setter that silently does nothing.**
An integrator raises `QueueCapacity` from 256 to 2048 on a congested client from the dashboard,
reads it back as 2048, and keeps losing requests at 256 forever.
*Fix:* throw `InvalidOperationException` from both setters once the queue exists, with the server's
own message shape ("… can only be changed while the client is disabled").

**Row 57 — a queued write vanishes on dispose.**
A device block writes a safe baseline from `Stopping()`; the actor's scope disposes the client, the
queue's writer is completed and its CTS cancelled, and the write is neither sent nor reported — no
callback, no receipt, no link record. RFC 0018 § 9 records this as the corrected claim, and three
fielded consumer blocks depend on it arriving.
*Recommendation:* drain the channel on `Dispose`, completing each remaining request through
`HandleRequestFailed(new RequestDroppedException(name))` as the disposed-enqueue path already does.
That is a new callback a fielded error handler will start receiving during shutdown, so it is the
operator's call. The alternative — correcting `ILogicBlockModbusTcpClient.cs:38-41` to say the
queued ones are dropped silently — documents a hole rather than closing it.

**Row 59 — shutdown logs an Error per queued request.**
A gateway with six Modbus blocks redeploys; each block's queue holds a handful of requests, and the
log pipeline takes tens of `Request 'ReadHoldingRegistersAsUShort' failed` lines at Error for an
ordinary restart — the flood the comment three lines up exists to prevent.
*Fix:* add `ModbusOutcome.Cancelled` to the quiet arm at `DeviceRequest.cs:94`.

**Row 62 — `Disconnect` on a disabled client is silently skipped.**
A block disables its client, calls `Disconnect(this, onDone, onError)` to release the socket, and
neither callback ever runs; the block waits forever on a completion that cannot arrive.
*Fix:* documentation. Add the gate to `ILogicBlockModbusTcpServer`'s sibling wording on
`ILogicBlockModbusTcpClient.cs:178-209` — the behaviour is right (row 7's rule), the promise is
incomplete.

**Row 65 — a negative `MaxQueuedAge` reads back as "no limit".**
A bench resolving `IRequestQueue` from the container sets `MaxQueuedAge = TimeSpan.FromSeconds(-1)` to
force expiry, reads it back as `null`, and every request runs however old it is — the opposite of what
was asked, silently. *(The sketch first named a TestKit bench as the reader; it cannot reach this —
`FakeModbusTcpHarness` registers `SynchronousRequestQueue`, whose property carries no sentinel. That
divergence is now its own ledger line, owner `TKIT`.)*
*Fix:* refuse a non-positive value in `RequestQueue`'s setter, matching the client's, so the `-1`
sentinel is reachable only from `null`.

**Row 68 — the 64-bit word-order guard is inside the loop.**
A device returns an empty register frame for a `ReadHoldingRegistersAsDouble` with a cast-invalid
`WordOrder64`; the swap returns silently, the cast yields an empty array, and the block's success
callback fires with no values instead of the `Invalid` receipt its two sibling orders produce.
*Fix:* hoist the enum check above the loop, as `SwapBytes` (`:50`) and `SwapWords(WordOrder32)`
(`:71`) already do.

**Row 78 — the SDK sends a request the protocol cannot honour.**
A block reads 200 holding registers; the device answers `IllegalDataValue` and the block sees a
`DeviceError` with no hint that the request, not the device, was wrong — or the device drops the
frame and the block sees a `Timeout` and blames the network.
*Recommendation:* refuse in the client before the wire — 125 registers for FC3/FC4, 123 for FC16,
2000 bits for FC1/FC2 — with `InvalidCountException` and an `Invalid` receipt, matching what
`Vion.Examples.ModbusTcp` already does one layer up. No call in the first consumer's 84 files reads
above 40 registers, so nothing fielded changes.

**Row 85 — a value width below two bytes divides by zero.**
A consumer resolving the public `IModbusDataConverter` to decode a byte-wide field calls
`ConvertCountToQuantity(4, 1)`; `registersPerValue` is 0, the overflow branch computes
`ushort.MaxValue / 0`, and the block sees a bare `DivideByZeroException` classified as
`TransportError` — a faulted link for an argument mistake.
*(park)* Two guards, one per method, but the real question is whether these two types should be
public at all (row 156); fixing the arithmetic without answering that hardens a surface the SDK may
not want.

**Row 93 — an empty write reports an address error.**
A block calls `WriteAsString(addr, "")` after a null-coalesce, and the exception says the access
"lies outside the declared extent of 64" — the author checks their extents, which are fine.
*Fix:* throw `ArgumentException` naming the empty payload, as `WriteRaw`'s odd-length arm already
does, and leave `InvalidServerAddressException` for what its name says.

**Row 99 — a nested `Sync` disarms the deadlock guard.**
A block factors register access into two helpers, each opening its own `Sync`, and calls one inside
the other; after the inner one returns, `IsEnabled = false` inside the outer callback no longer
throws — it calls `Stop()`, which joins request handlers waiting for the lock the callback still
holds, and the actor thread never returns.
*Fix:* make `_inSyncCallback` a depth counter, or save and restore its previous value in each
`finally`.

**Row 113 — a disposed server reports itself enabled.**

`IsListening == false`, which no documented state pairs; setting `IsEnabled = false` then calls
`Stop()` on a disposed server, logged as a teardown race.
*Recommendation:* have `Dispose` set the flag to `false` first. It changes what a block's own
teardown observes, and 23 consumer files use this interface, so it is the operator's call.

**Row 116 — two instant types on one surface.**

offset, and a comparison between them needs a conversion the author did not expect.
*(park)* Changing either is source-breaking for the consumer's 23 files and for the DevHost's struct

**Row 130 — a throwing callback is contained on TCP and escapes on RTU.**

*Fix:* guard the two queued-wait writes on the outcome having been queued at all — every outcome

**Rows 150 / 151 — a factory-created client or server is never reclaimed.**

## Relay notes for the PR body

**A Modbus block's build is unchanged; its runtime behaviour refuses more, and tells it more.**

**New refusals a fielded configuration can hit.** `Port` refuses 0 on the Modbus TCP client and on the
hosted server — it is the ephemeral-port sentinel and what an unset configuration field binds to; the
first consumer already declares `Minimum = 1`. `ConnectionTimeout` and `DefaultOperationTimeout` refuse
a non-positive duration, on the RTU contract as well as on TCP; a zero connect timeout used to fault
every connect and arm a backoff against a device that was answering. `MaxQueuedAge` refuses one on the
queue itself, where the "no limit" sentinel used to swallow it and mean the opposite. `QueueCapacity`
and `QueueOverflowPolicy` throw when changed after the queue exists instead of silently keeping the old
value — re-setting the value already in force is still a no-op. And a read or write whose quantity
exceeds the protocol's data unit is refused before the wire with an `InvalidCountException` and an
`Invalid` receipt: 125 registers to read, 123 to write, 2000 bits to read, 1968 to write, published as
`ModbusProtocolLimits`. No call in the first consumer approaches any of them — its largest is 40
registers.

**Behaviour a block sees that it did not before.** A request still queued when the client is disposed
now completes with a `Cancelled` receipt instead of vanishing, which makes the surface's own
"requests already queued or in flight are cancelled" true; whether a write issued from a stop hook
*arrives* is still the runtime's grace period to decide. Disposal no longer logs an Error line per
queued request. `DefaultOperationTimeout` is bound when the call is accepted, as it has always been
documented and was not. `LastQueuedWait` and `MaxQueuedWait` are no longer cleared by a request that
was refused before it was ever queued. A disposed server reads `IsEnabled == false`. A nested `Sync`
no longer disarms the re-entrancy guard for the rest of the outer callback, and a snapshot accessor
kept past its callback now refuses instead of writing the live buffers unlocked. An empty read or
write on a server area is an `ArgumentException` naming the payload, not an address error. The 64-bit
word-order refusal fires on any buffer length, and a ragged buffer is treated alike across the three
swaps.

**Documentation that was wrong.** `IModbusClient` and `ModbusLinkSummary` said locally decided
outcomes "are still counted"; eight of the ten have a counter and `Invalid` and `Cancelled` have none.
`Disconnect`'s remarks called it idempotent and never named the `IsEnabled` gate that makes it invoke
neither callback. The connect-timeout message rendered its seconds in the caller's culture. Two
transposed log calls meant the multiple-coil write never logged "Executing" and the multiple-register
write never logged "Executed". The `modbus-smoke` skill said the TestKit's fake proxy "can prove none
of" the link policy, when it substitutes the proxy and the real policy runs above it.

**Inside the repository.** Both Modbus RFCs are absorbed and deleted, leaving three in `docs/rfcs/`;
seven living citations were re-pointed. `docs/specs/modbus.md` is new — 106 criteria, eleven of them
GAP with a reason. All 466 tests in the area's three suites and the TestKit's two policy suites cite a
criterion, and the style gate holds over them with no exemption.
