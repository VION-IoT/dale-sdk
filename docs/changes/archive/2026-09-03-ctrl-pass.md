## At a glance

### Summary

The sixth SDD area pass. `CTRL` is what a running `Vion.Dale.DevHost` guarantees a caller: in
process (`IDevHost`, `IDevHostControl`), over HTTP and SignalR, and on stdout to the process that
spawned it — plus how a host is built, booted, recycled into a new generation, switched between
clock modes and torn down. Phase A extracts the behavior table; Phase B mints the criteria, fixes
what the operator classifies as `fix`, rewrites the area's own suites, absorbs six RFCs and lands
`docs/specs/devhost-control.md` with `trace: enforced`.

### Spec implications

Creates `docs/specs/devhost-control.md` (`D1`) — a new Tier A page carrying the whole `CTRL`
contract: host lifecycle and teardown ordering, the supervised recycle protocol, the process
contract (`DALE_DEVHOST_*`, the readiness line, the export receipts and handshake), folder-driven
boot, the in-process control surface member by member, the HTTP route table with its status codes
and `reason` tokens, the hub's events and its replay-on-connect, the run registry's snapshot, the
exported configuration's envelope, and the log sink's bound.

`docs/devhost-conventions.md` § 8 (recycle-on-run and the write refusal) becomes a pointer at the

`AC-SCEN-012.6`'s wording (ledger row 3's seam), and `docs/specs/config-gating.md`

### Decisions

- `D1` — **the page is `docs/specs/devhost-control.md`.** The brief left the name to this session.
  "DevHost control" is what every consumer already calls it (`IDevHostControl`, `/api/control/*`,
  the smoke skill's "control API"), and `devhost-` prefixes the two sibling files a reader will
  reach for next (`devhost-conventions.md`, `Vion.Dale.DevHost.Web/CLAUDE.md`). Rejected:
  `devhost.md` (the SPA and the SmokeHost are Tier C, so "the DevHost" over-promises) and
  `control-api.md` (the in-process half and the stdout half are not an API).
- `D2` — **the exported configuration splits by who owns the field, not by who serializes it.** This
  page states the *envelope* (`TopologyName`, the five collections, the omission rule, the two
  export modes, and that the live view — not the definition view — is what is exported); it cites
  `AC-GATE-012.3` / `AC-GATE-012.4` / `AC-GATE-012.9` for the live-view resolution and the parameter
  values, `AC-GATE-010.*` for the parameter projection, `AC-INTRO-007.*` for member schemas and the
  member vocabulary, and `AC-SCEN-008.7` for the contract wire-field leaves.
- `D3` — **the mock handlers are stated as the host's cache-and-publish seam.** `EMIT` owns what the
  SDK emits; this page owns what the host does with an emission (the last-known-value cache, the
  `DevHostEvent` projection, the write acknowledgement, the hub broadcast, the replay on connect).
  Any row that would restate an emission rule cites `EMIT` instead.
- `D4` — **`dale dev`'s option surface stays `CLI`'s.** This page states the process contract from
  `DevHostWebRunner`: the four `DALE_DEVHOST_*` variables the runner reads, the readiness line, the
  export receipts, and the fact that an export completes when the *file* appears. `dale dev`'s
  flags, help text and boot window are read here as a consumer and specified in `CLI`'s pass.
- `D5` — **the SPA export-without-import check is measured before it is shipped.** Brief point 6
  time-boxes it to one hour and makes shipping conditional on a clean baseline; `DC-9` carries the
  measured baseline and the disposition.
- `D6` — **the four ledger entries enter the table with a recommendation** (rows 18–19 · 191 · 99
  and 130 · 193). The entries are the brief's, ratified; the recommendation is this session's.

### Error-model overview

The area has four refusal shapes, and which one a caller gets is itself the contract.

1. **Build-time** — `DevHostBuilder.Build()` throws before any actor exists.
2. **Start-time** — `DevHost.StartAsync` throws `InvalidOperationException`; nothing was bound, so
   the caller's `await using` is sufficient teardown. The supervised runner catches exactly this
   type, and only for a *switch* generation.
3. **Per-call** — `ServicePropertyWriteException` in process, its `400 { error, reason, property }`
   over HTTP; and the `409 { error, reason }` family for a state the host is not in.
4. **A recorded warning** — an initialization failure the host survives, visible only in the log
   stream. Rows 18–19 are where that shape is a defect rather than a design.

The rule the page states plainly: a refusal a caller can act on is a status code plus a token; a
refusal a caller cannot act on is a thrown exception. There is no third category — a silently
successful no-op is a defect wherever this pass found one (rows 104, 105, 137, 147, 148, 159).

### A defect that was not there — and what produced it

Four separate readings during this tier said the host **died** on a recycle: `202` from
`/api/control/reset`, then `ERR_CONNECTION_REFUSED` on everything after it, with the process's own
log ending at `Reset requested - recycling host (generation 2)...` and no failure receipt. It
reproduced on this branch and, on a checkout of `7535961`, on the pre-pass code as well — which was
the first thing that made it suspect as a finding rather than a regression.

It was neither. Two of my own mistakes stacked:

- **Leftover processes.** Every earlier SmokeHost I had started was still holding port 5000, so the
  *next* generation could not bind. One of those runs is where this pass's new failure receipt
  actually earned its keep — it is the only reason the cause was ever visible:
  `{"failed":true,"port":5000,"generation":1,"topology":null,"reason":"The development host could not
  bind port 5000: Failed to bind to address http://127.0.0.1:5000: address already in use. Another
  host is probably already serving it - stop it, or start this one on a different port."}`
- **Impatience.** With the port genuinely free, the recycle simply takes longer than the eight
  seconds I was allowing. Polling it out:

  ```
  t=10s status=200 readyReceipts=2
  ```

  Generation 2 was up; two `"ready"` receipts in the log; the process had been alive the whole time.

Independently, `RunFolderDrivenAsync` was probed in-process on a free port and recycled correctly:
`{"ready":true,"port":50681,"generation":1}` → `Reset requested` → `{"ready":true,"port":50681,"generation":2}`,
runner still running. No park row, no ledger line: there is no defect here.

## Relay notes for the PR body

Every wire-carrying change this pass makes, in the words a consumer needs. A client of the DevHost
API — the single-page application, the smoke skill, `dale dev`, the first consumer's
`devhost-explore` and `wallclock-verify` skills, any agent driving `/api` — reads this list to know
what moved.

- **A drive that reaches no block now answers `400`, where it answered `200`.**
  `POST /api/contracts/drive/{handler}/{provider}/{service}/{contract}` resolves the handler among the
  stand-ins the running host created and the endpoint among its wired configuration before sending
  anything, and refuses with `{ error, reason, contract }` — `reason` is `unknownHandler` or
  `unknownContract`. A client that checked only `response.ok` was previously told a poke took when
  nothing received it. *(rows 104, 105, 159.)*
- **An unknown block or member on a state read now answers `404`.**
  `GET /api/state/{block}` and `GET /api/state/{block}/{member}` answered `200 {}` and
  `200 {"value":null}` for a name the host does not carry — indistinguishable from a block that has
  published nothing. The in-process `GetProperty` / `GetAllProperties` keep their documented null and
  empty contract; only the routes changed. A skill that samples members by name learns of a rename
  instead of reading it as a null. *(rows 147, 148.)*
- **An unmatched `/api/` route now answers `404`, not the application shell.** The catch-all that
  serves the single-page application matched any path without a file extension, `/api/…` included, so
  a mistyped route answered `200 text/html`. A client that checks the status code no longer reports a
  host healthy on a typo. *(row 137.)*
- **A manual advance that is not a duration a clock can wait now answers `400`.**
  `POST /api/control/advance?seconds=` guarded only `seconds <= 0`, which is false for a value that is
  not a number: `NaN`, `Infinity` and an overflowing value each escaped as a `500`. The bound is the
  one a scenario's durations already carry (`AC-SCEN-003.2`). *(row 161.)*
- **Two conflicts gained a `reason` token.** `POST /api/topologies/{id}/switch` on an unsupervised
  host now carries `reason: "notSupervised"`, and `POST /api/scenarios/{id}/apply` against the wrong
  topology carries `reason: "topologyMismatch"` — like the five conflicts that already had one. A
  client telling them apart no longer has to match prose. *(row 165.)*
- **`GET /api/control/status` gained `blockFailures`.** An array, empty on a healthy host, of the
  handler exceptions the actor middleware caught per block — `{ logicBlock, message, error, timestamp }`.
  A block whose configuration, binding or start hook threw used to leave the host reporting itself
  started, its members reading their defaults, and one line in the log. `IDevHostControl.RecordedFailures`
  is the same list in process. *(row 19, the finding ledger's `GATE` row 66.)*
- **A start that no block acknowledges now fails instead of hanging.** The acknowledgement wait is
  routed through the registered clock, so on a stepped host — `dale dev --stepped`, the smoke skill's
  own boot — a block whose start hook threw left a due-time that never arrived and the boot never
  returned at all. *(row 20.)*
- **A failed boot prints a receipt.** `{"failed":true,"port":…,"generation":…,"topology":…,"reason":…}`
  on standard output before the process ends — the counterpart of the readiness line an agent waits
  for. A port already in use is now named as such rather than surfacing as a framework stack trace.
  *(rows 22, 45.)*
- **The readiness line carries `generation` from both entry points.** The unsupervised
  `DevHostWebRunner.RunAsync(host, …)` printed `{ready, port}` while the supervised loop printed
  `{ready, port, generation}`; a parser written against one did not read the other. *(row 49.)*
- **A topology that is gone, or that no longer builds, no longer takes `dale dev` down.** The
  supervisor builds the next generation inside its guard now, so a file deleted between the editor's
  listing and the switch falls back to the running topology exactly as an unregistered block already
  did. *(row 44.)*
- **A second scenario on one stepped generation now recycles.** `POST /api/scenarios/{id}/apply` asked
  whether *this* scenario had run before; it asks whether **any** has. A bench that runs several
  scenarios in a row — the Player, the smoke skill, `wallclock-verify` — sees a `202 { recycling }`
  where it saw a `202 { runId }`, and gets the clean slate `AC-SCEN-012.10` promises instead of the
  previous run's leftovers. Every client already performs the re-apply round trip. *(row 171.)*
- **Two builder knobs, and no new interface members.** `DevHostBuilder.WithSafetyBudgets(DevHostBudgets)`
  and `WithDeterministicStepping(startUtc, quiescenceBudget)` set the host's four real-time backstops —
  the write-acknowledgement window, the start-acknowledgement backstop, the stop-sequence budget and
  the quiescence ceiling — which were private constants. A consumer's integration harness can now
  reach the failures they bound without waiting them out. *(rows 99, 130, 20, 26.)*
- **A parameter's editor schema omits a bound it cannot carry.** A `NaN` minimum was published as `0`
  and a finite bound outside the integer range saturated to its extreme — limits the author never
  wrote. Editors resolving a topology's parameter schema stop showing them. *(row 191.)*
- **`OnResetRequested` refuses a second supervisor.** Attaching a second reset handler to one host
  generation used to replace the first silently, so the host answered a recycle request with success
  while nothing recycled; disposing any subscription token used to detach whichever handler was
  current. Only the runner attaches in this repository, so nothing in it changes. *(rows 123, 124.)*

> `<OP> <ID> -> <target> : <payload>`
