# EMIT area pass — service properties, measuring points and the emission policy

> Change doc — one in-flight change. The `Spec delta` below is distilled into the current-truth
> pages under `docs/specs/` in the implementation PR, then this doc is archived
> (`pwsh scripts/spec-change.ps1 archive emit-pass`). Process: `docs/spec-process.md`. Never put
> change narrative inline in a spec page — it lives here.

## At a glance

### Summary

Second SDD area pass. Turns the emission policy — the `MinInterval` / `MinChange` / `Immediate`
knobs on `[ServiceProperty]` and `[ServiceMeasuringPoint]`, the five-step gate they drive, the
change-threshold resolution behind a deadband, the six DALE diagnostics that validate them, and the
introspection node that reports them — into a current-truth spec page with an id-cited test suite.
Unlike the pilot the area is already heavily tested (114 tests in scope), so the yield is not
coverage but **consistency**: the sweep found the two halves of a dual-annotated member sharing one
attribute's knobs, and a family of knob values the analyzers pass and the gate then ignores.

### Spec implications

Creates `docs/specs/emission.md` (new, Tier A, `trace: enforced`) carrying `AC-EMIT-*` criteria for:
policy activation and gate construction (including knob inheritance from a `[ServiceInterface]`);
the five-step offer decision (dedup floor, `Immediate` bypass, deadband, leading edge, trailing
hold); the duration and deadband grammars and change-threshold resolution; the single coalesced
trailing-edge flush; the lifecycle edges (start seed, clear, reconnect re-assert, stop drain); the
six authoring diagnostics DALE034–DALE039; and the `runtime.throttle` introspection node. No
existing page changes. `_invariants.md` gains nothing — no cross-cutting rule emerged that a second
area would also cite.

### Consumer-visible change — relay this in the PR body

**A dual-annotated member's measuring-point stream no longer inherits the `[ServiceProperty]` knobs.**
Until now, a member declaring both attributes had *both* streams gated — and both introspection
entries reported — from whichever `[ServiceProperty]` it carried; a `[ServiceMeasuringPoint]`'s own
`MinInterval` / `MinChange` / `Immediate` were silently ignored. Each stream now reads its own
attribute, and a `[ServiceMeasuringPoint]` that declares no knobs falls to the attribute defaults
(`MinInterval = "250ms"`, no deadband, not immediate) instead of borrowing the property's.

**Who this moves.** In `logic-block-libraries` there are **14** dual-annotated members; **13** of them
declare no knobs on the `[ServiceMeasuringPoint]` and today ride the property's interval. On the
version bump after this ships, those 13 measuring points drop from the property's interval to the
250 ms default — a rate increase, not a loss of data. **They need an explicit `MinInterval` on the
`[ServiceMeasuringPoint]` before that bump.** The 14th already declares its own knobs and gains
them.

`Vion.Examples.Emission` (this repo) is the same shape and is pinned to a published package, so its
`Power` badges stay identical until `scripts/set-version.ps1 -Scope references` runs after the
release that carries this.

### Decisions

- `D1` — The area's anchors are **not** the PublicApi manifest entries for the gate. The whole
  `Vion.Dale.Sdk.Emission` namespace is `internal` except `IChangeThreshold<T>`, and that one public
  type carries no `[PublicApi]`, so the manifest shows only the two attributes, `MeasuringPointKind`
  and `EmissionPolicyMode` (A4). The anchors used instead are the three-knob set on the two
  attributes (A1), the six DALE034–DALE039 descriptors (A2), and the `runtime.throttle` JSON node
  (A5). The `IChangeThreshold<T>` marking is itself row 60.
- `D2` — Rows over the `internal` gate types (`Throttler`, `ThrottlePolicy`, `EmissionEquality`,
  `DurationParser`, `ChangeThresholdRegistry`) are stated as behaviors of **a declared member's
  emission**, not of the classes, because that is the consumer-observable seam. Their tests may
  still drive the internal type directly (`InternalsVisibleTo` grants it), but the AC sentence never
  names one.
- `D3` — The six emission diagnostics' 44 analyzer tests live in `Vion.Dale.Sdk.Generators.Test`,
  the `ANLZ` area's project. They are **mapped, not rewritten** (the pilot's D3 precedent for a
  cross-area anchor). Rows 56–57's fixes add tests there; the rest of that project is untouched.
- `D4` — `Vion.Examples.Emission` is **Tier C**: its 7 xunit tests are not rewritten to the Tier A
  style and cite no ids. They are read as the consumer lens (rows 55, 59), and one of them is
  corrected where a fix invalidates its premise.

### Reviewer's questions

1. **(propose-and-wait)** Row 55 is the pass's blocker-shaped finding: on a dual-annotated member
   **both** the measuring-point gate and the measuring-point introspection entry read the
   `[ServiceProperty]` knobs, so a `[ServiceMeasuringPoint(MinInterval = "500ms", MinChange = "1")]`
   declared beside a `[ServiceProperty(MinInterval = "2s")]` is inert. This is exactly the half of
   "#104 independent per-stream gating" that the #104 fix did not do — it separated the gates' state
   but not their policy. The fix is two one-argument threadings (`ConfiguredFrom` and
   `ExtractThrottle` learn which stream they serve) plus their call sites, all internal. My
   recommendation: `fix` in this pass. It sits at the size guard's edge — say the word and it becomes
   its own change doc instead.
2. **(propose-and-wait)** Rows 56–58 are one family: values the analyzers accept and the gate then
   silently ignores — a negative `MinInterval` (throttling off, `ThrottleDisabled` still `false`), a
   negative `MinChange` (deadband never fires), and `MinChange = ""` (gate ignores it, introspection
   surfaces a badge for it). Each fix is a few lines in `EmissionAttributeHelper` /
   `MinChangeUnparseableAnalyzer` plus test rows. Recommendation: `fix` all three; they are one
   defect wearing three hats, and fixing one leaves the class open.
3. **(propose-and-wait)** Row 59: `MinInterval = "250"` and `MinInterval = "250ms"` are the same
   duration, but introspection's default-suppression compares the **string**, so the first emits a
   `runtime.throttle` node and the DevHost renders a unitless badge (`throttle 250`) while the second
   emits nothing. Fix (compare parsed durations) or `intended` (the badge mirrors what you wrote)?
   I lean `fix`; either way the page must state which.
4. **(decide-and-document)** Row 60: `IChangeThreshold<T>` is the one type a consumer must implement
   to deadband a custom value type — the emission example does
   (`examples/Vion.Examples.Emission/Vion.Examples.Emission/Emission/ThreePhaseChangeThreshold.cs:13`)
   and both attributes' XML docs instruct it — yet it carries no `[PublicApi]`, so it is absent from
   `docs/snapshots/publicapi-manifest.json` and from the generated API reference. Adding the marker
   moves the manifest snapshot (the bot commits it) and arms the XML-doc analyzer on the type, which
   already has docs. Recommendation: `fix`.
5. **(decide-and-document)** Surface minimalism (`sdk-surface-conventions.md` D1, the pilot's Q3
   shape): `ChangeThresholdRegistry.Register<T>` and the two-argument
   `ChangeThresholdRegistry.TryResolve(Type, out …)` have **zero production callers** — only tests
   (verified repo-wide this session). `Register<T>`'s own XML doc advertises that it "allows
   libraries to register a custom `IChangeThreshold<T>`", which no library can do: the class is
   `internal`. Delete both and correct the doc, or leave them?
6. **(ratified — cite)** RFCs to absorb: `docs/rfcs/0004-emission-policy.md` and
   `docs/rfcs/0014-emission-showcase-example.md`, per the brief. Both deleted in Phase B with the
   reference sweep; `0005`, `0012`, `0014-devhost-scenario-authoring`, `0016`, `0017` stay.
