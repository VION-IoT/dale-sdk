# GATE area pass — instantiation parameters and config-time structural gating

> Change doc — one in-flight change. The `Spec delta` below is distilled into the current-truth
> pages under `docs/specs/` in the implementation PR, then this doc is archived
> (`pwsh scripts/spec-change.ps1 archive gate-pass`). Process: `docs/spec-process.md`. Never put
> change narrative inline in a spec page — it lives here.

## At a glance

### Summary

Third SDD area pass. Turns config-time structural gating — the `[InstantiationParameter]` value
channel that runs before `Configure`, the `[IncludedWhen]` predicate the three declarative binders
resolve against it, the definition/live binding split, the two DALE diagnostics that police the
declaration, and the four wire fields the gates reach — into a current-truth spec page with an
id-cited test suite. The area is thinnest where it is riskiest: 19 tests in the rewrite over an
11-site production surface, with the parameter *value* path (types, ranges, nulls, decode failures)
almost entirely uncovered. The yield is coverage **and** a family of silences: a runtime write that
reverses a parameter after its gates resolved, a gate placement the analyzer does not judge, and a
DevHost boot that reports success over a block that never initialized.

### Spec implications

Creates `docs/specs/config-gating.md` (new, Tier A, `trace: enforced`) carrying `AC-GATE-*` criteria
for: the parameter value channel (application before `Configure`, identifier resolution, the decode
grammar and its failures, persistence exclusion, runtime immutability); gate evaluation (fail-closed
strict evaluation, the parameter-only context, the JSON-scalar encoding); the `Definition` / `Live`
binding split; what an excluded interface binding, contract binding and service-bearing component
each lose; the runtime message paths that tolerate a gated-out endpoint; gates and persistence (no
dormancy); the four wire fields (`services[].includedWhen`, the binding `IncludedWhen` annotation,
`schema.readOnly`, `runtime.instantiationParameter` + `runtime.default`); and DALE043/DALE044.
`docs/specs/emission.md` and `docs/specs/plugin-loading.md` are untouched. `_invariants.md` gains
nothing: the one cross-cutting candidate — fail-closed at bind, fail-open in the editor — is already
stated in `sdk-surface-conventions.md` § 7 and is cited, not restated.

### Decisions

- `D1` — The area's anchors are the **two attributes** (A1), the **two DALE descriptors and the
  fifteen rules they carry** (A2), the **four gating fields the introspection JSON emits** (A5, read
  out of `Vion.Dale.LogicBlockParser` over a probe plugin this session), and the **PublicApi manifest
  entries** (A6, exactly two). The gate model under `Configuration/` is `internal` except
  `BindingMode`, so every row is stated as behavior of *a declared member*, never of `InclusionGate`.
- `D2` — The 26 analyzer tests in `Vion.Dale.Sdk.Generators.Test` (`IncludedWhenPredicateAnalyzerTests`,
  `InstantiationParameterAnalyzerTests`) live in the `ANLZ` area's project. They are **mapped, not
  rewritten** (the pilot's D3, the EMIT pass's D3). Row 61's fix adds a test there; the rest of that
  project is untouched.
- `D3` — The TestKit's `WithInstantiationParameter` is in scope as **gating semantics**: it is the
  only supported way a test drives the parameter channel, and it exercises the same encode/decode
  path the config payload uses (row 53). Its ergonomics — the selector overload, the builder's own
  validation — are `TKIT`'s and are recorded out of scope in A8.
- `D4` — `examples/Vion.Examples.Gating` is **Tier C**: its 16 xunit cases are not rewritten and cite
  no ids. It is read as the consumer lens (rows 24–27, 53); its README is corrected where row 67
  falsifies it, which is a docs edit, not a test rewrite.
- `D5` — `Vion.Dale.DevHost.Web/wwwroot/wiring.js` is Tier C (SPA internals, `spec-process.md`
  § Corpus). Its gate handling is walked as the operator lens and recorded in row 57's evidence, but
  it declares no criteria and is not rewritten.

### Reviewer's questions

1. **(propose-and-wait)** Row 60 is the pass's sharpest finding: a `SetServicePropertyValue` reaching
   a running block is applied to an `[InstantiationParameter]` property like any other — verified this
   session (`Count` 2 → 3 after `Build()`). The attribute's own XML doc says the opposite twice
   ("never settable at runtime", "every SetPropertyValue is rejected"), and DALE044 spends two of its
   rules — auto-property, no in-code assignment — enforcing exactly the read-back honesty this breaks:
   after the write the block reports a parameter value its bound member set does not match. The SDK's
   general posture is that `readOnly` is a wire flag the cloud enforces, so the options are (a) add a
   parameter guard in `HandleSetServicePropertyValueRequest` and reject the write, or (b) leave the
   behavior and correct the two doc sentences. My recommendation: **(a)** — a parameter is the one
   `readOnly` whose value is load-bearing for structure, and the guard is one site.
2. **(propose-and-wait)** Row 61: `[IncludedWhen]` on a member of a **component** type gets no
   diagnostic and is silently ignored at bind — confirmed with a positive control in the same
   compilation (the identical mistake on the block reports DALE043; on the component, nothing).
   `InstantiationParameterAnalyzer` already walks every class and reports DALE044 for the mirror-image
   misplacement, so the fix is to give `IncludedWhenPredicateAnalyzer` the same reach. Recommendation:
   `fix`. It widens what an existing **error**-severity rule reports, which can redden a consumer
   build on the next version bump — say the word if that makes it a `park` instead.
3. **(propose-and-wait)** Row 65: a second `InitializeLogicBlock` on an already-configured block is
   accepted, re-applies the parameters and re-runs the binders over the **same** `ServiceBinder` — so a
   gate that flips *open* adds its member and a gate that flips *closed* leaves the old member bound
   (both verified this session). Nothing in this repo sends a second one; the documented contract is
   that changing a parameter re-activates and recycles the block. Options: (a) refuse a second
   configuration, naming the recycle contract in the exception, or (b) state the additive behavior as
   intended. Recommendation: **(a)** — a half-applied reconfiguration is the silent-wrongness class
   this repo fixes rather than documents, and refusing is a guard plus a test.
4. **(decide-and-document)** Row 66: a DevHost topology naming an unresolvable parameter identifier,
   or a value that will not decode, reports **"Development host started successfully"** and leaves the
   block uninitialized — the initialize throw happens inside the actor, after `SendTo` returned, so
   `DevLogicSystemInitializer`'s `catch` at `:435` never sees it. The operator sees a block whose
   properties all read null and a service list computed from the *defaults*, which disagrees with the
   nothing the block actually bound. The cheap area-local half is to resolve each topology
   `instantiationParameters` key against the block type's `[InstantiationParameter]` properties in
   `DevTopologyLoader`, alongside the `mappingErrors` collect-then-report already there — that catches
   the typo case at load / validate / save, where the operator is. The decode case, and the general
   "an actor failed to initialize but the host says started" gap, are bigger and belong to `CTRL`.
   **My call unless overruled: fix the loader half, park the rest.**
5. **(decide-and-document)** Rows 62 and 64 are one family: predicate strings the runtime refuses that
   the definition view passes through unchecked. `[IncludedWhen("")]` is reported as *ungated* in the
   introspection JSON (`string.IsNullOrEmpty` at three sites) and then fails every bind; an
   unparseable or unresolvable predicate is emitted verbatim to the wire and fails every bind. DALE043
   is the compile-time half, but it is an analyzer — suppressible, and absent from any project that
   does not wire the pack (`sdk-surface-conventions.md` § 5, and probe 3 below hit exactly that).
   Row 62 (the empty string) is a three-site inconsistency and I take it as a `fix`; row 64
   (parse-checking in `Definition` mode) would make `dotnet pack` fail on a block that is broken
   anyway, which is a better failure but a behavior change to the pack path — recorded as `park`
   unless you want it in.
6. **(ratified — cite)** RFCs to absorb: **one** — `docs/rfcs/0016-config-time-structural-gating.md`,
   per the brief. Deleted in Phase B with the reference sweep. `0017` and `0019` stay; the
   presentation-visibility half of `0017` is `INTRO`'s and no row of this pass needs it.
7. **(decide-and-document)** `BindingMode` is `public` and unmarked, so it is absent from
   `docs/snapshots/publicapi-manifest.json` and from the generated API reference —
   `Vion.Dale.Sdk.Configuration` declares no `[assembly: PublicApiNamespace]`, so DALE014 never judged
   it. Unlike the EMIT pass's `IChangeThreshold<T>`, no consumer implements or names it: `Configure`
   is `internal`, and the only public surface exposing it is `ILogicBlockConfigurationBuilder.Mode`,
   itself unmarked. Recommendation: leave both as they are and state the split in the page rather than
   widen the documented surface (`sdk-surface-conventions.md` D1). Marking `[InternalApi]` would be
   tidier but arms DALE014 over the whole namespace, which is `BIND`'s pass to absorb.
