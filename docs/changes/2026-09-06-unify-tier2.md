# Unification pass, Tier 2 — the level fixes

> Change doc — one in-flight change. The `Spec delta` below is distilled into the current-truth
> pages under `docs/specs/` in the implementation PR, then this doc is archived
> (`pwsh scripts/spec-change.ps1 archive <slug>`). Process: `docs/spec-process.md`. Never put
> change narrative inline in a spec page — it lives here.

## At a glance

### Summary

Tier 1 unified the corpus's conventions without touching a criterion's level. Tier 2 fixes the
level: five criteria whose subject was a test suite or the source tree are retired into `SYS-` rules
or prose, seven field-level leaves are merged into the rule they were rows of, one composite is
split, and the cross-page restatements become citations. Twelve ids leave the corpus and two enter
it; no criterion's **behaviour** changes, no production code changes, and every moved citation's
mutation was re-derived and run red-then-green before the citation landed.

### Spec implications

`_invariants.md` becomes a traced page and `SYS-REL-001` loses its GAP tail, because both roster
proofs now cite it. `testkit.md` loses three criteria and its Test-discipline section becomes prose;
`modbus.md` loses one and its Test-discipline section likewise; `io.md` loses one; `analyzers.md`,
`emission.md`, `plugin-loading.md` and `scenarios.md` each lose a merged leaf; `cli.md` gains
`AC-CLI-001.11` from a split. `devhost-control.md`, `testkit.md` and `scenarios.md` gain prose
citations where they had narrated a neighbour's rule.

### Decisions

- `D1` — a criterion is retired to **prose on its own page**, not deleted, whenever the thing it
  stated is real but is discipline rather than a consumer observable. The page keeps saying it; it
  just stops being a criterion.
- `D2` — a merged family's tests are **not** collapsed into one `[DataRow]` method where each
  already drives its own mechanism. Collapsing would rewrite assertions and re-derive mutations for
  no gain; three tests citing one criterion is the corpus's normal shape.
- `D3` — a merge that would produce a criterion no single mutation reddens is not made. This
  declined `AC-CLI-006.10`–`006.13` (below).
- `D4` — a split is made only where both halves have a test and a mutation of their own. This
  declined `AC-PLUG-005.8` (below).

## Full design

### 1. The mechanism-level retirements

| id | was | now | its tests |
|---|---|---|---|
| `AC-TKIT-013.4` | the release roster, stated from a kit's side | `SYS-REL-001` in `_invariants.md`, which becomes a traced page | both roster proofs re-cited to `SYS-REL-001` |
| `AC-MODB-019.1` | "keep the real-socket integration tests passing" | prose in `modbus.md`'s Test-discipline section | `PublishInputRegistersToWire` → `AC-MODB-005.1`; `RoundTripVgtShapedCycle` → `AC-MODB-013.1` |
| `AC-TKIT-014.1` | "test each kit from its own project" | prose in `testkit.md`'s Test-discipline section | its test is **kept, uncited**, as a premise test; the class summary says so |
| `AC-TKIT-014.2` | "leave another area's proof cited to that area" | the same prose | its test is **deleted** — see below |
| `AC-IO-010.1` | "ship the two packages as one design" | prose in `io.md`'s Mirror section | none (it was GAP) |

`AC-TKIT-014.2`'s test asserted only that *some* `AC-EMIT`/`GATE`/`LIFE`/`MODB` citation exists in
two kit test projects. `spec-trace` is the real gate for that and it **hard-fails**: drop a foreign
citation and the criterion it proved is orphaned on its own page, giving
`spec-trace: FAIL - N id(s) with no test reference` and exit 1. The deleted test added nothing the
gate does not already catch, and caught nothing the gate misses.

`SYS-API-001` keeps its `GAP:` tail — the manifest is a snapshot the CI bot regenerates and
auto-commits, which no in-process test can construct — and therefore keeps its whole bullet on one
line, because `spec-trace` reads the marker from the line that declares the id. That is why the
coordinator's "wrap both `_invariants.md` bullets" nit is only half done: `SYS-REL-001` is wrapped,
`SYS-API-001` cannot be.

`scripts/spec-lint.ps1`'s declaration regex now reads `(?:AC|SYS)-`, so the label and `SHALL` checks
cover `_invariants.md`'s bullets. Three self-test cases: a `SYS-` bullet with a bad label fails, one
without `SHALL` fails, a well-formed one passes.

## Spec delta (to distill)

> The machine-readable change, one line per id. Grammar:
> `<OP> <ID> -> <target> : <payload>`
>
> - `OP` ∈ `ADDED` | `MODIFIED` | `REMOVED`
> - `target` is **repo-root-relative** (normally `docs/specs/<page>.md`)
> - `payload`: for `ADDED`/`MODIFIED` the EARS text; for `REMOVED` the reason
>
> On the implementation PR each line is applied into the named target; `spec-change.ps1 archive`
> refuses until every line is applied. The `ID` must be an exact token greppable in the target
> after distill (backticks stripped) — a real `AC-`/`SYS-` id, never an ad-hoc label.

- REMOVED AC-TKIT-013.4 -> docs/specs/testkit.md : a repository release rule, not a kit behaviour — hoisted to `SYS-REL-001` in `docs/specs/_invariants.md`, which both roster proofs now cite.
- REMOVED AC-MODB-019.1 -> docs/specs/modbus.md : its subject was a test suite; the section states the acceptance bar in prose and its two tests are re-cited to `AC-MODB-005.1` and `AC-MODB-013.1`.
- REMOVED AC-TKIT-014.1 -> docs/specs/testkit.md : its subject was the test tree; stated as prose, and its test kept as an uncited premise test.
- REMOVED AC-TKIT-014.2 -> docs/specs/testkit.md : its subject was the test tree; stated as prose, and its test deleted because `spec-trace` hard-fails on exactly what it asserted.
- REMOVED AC-IO-010.1 -> docs/specs/io.md : a source-tree property and an authoring discipline, not a consumer observable; stated as prose in the Mirror section.
- REMOVED AC-PLUG-008.2 -> docs/specs/plugin-loading.md : a row of `AC-PLUG-008.1`'s rule, which now names eager loading as one of its three sites.
- REMOVED AC-PLUG-008.3 -> docs/specs/plugin-loading.md : a row of `AC-PLUG-008.1`'s rule, which now names assembly resolution as one of its three sites and carries its subdirectory clause.
- REMOVED AC-EMIT-013.6 -> docs/specs/emission.md : a row of `AC-EMIT-013.2`'s rule, which now names `minChange` and `immediate` as two of the three parts a default omits.
- REMOVED AC-MODB-006.2 -> docs/specs/modbus.md : a row of the port's own rule, now stated whole by `AC-MODB-006.3`.
- REMOVED AC-SCEN-004.3 -> docs/specs/scenarios.md : a row of `AC-SCEN-004.2`'s comparand-shape rule, which now names the `equals`/`notEquals` shape.
- REMOVED AC-SCEN-004.4 -> docs/specs/scenarios.md : a row of `AC-SCEN-004.2`'s comparand-shape rule, which now names the `oneOf` shape and its membership semantics.
- REMOVED AC-ANLZ-010.3 -> docs/specs/analyzers.md : its own GAP tail stated that the mechanism is `AC-ANLZ-020.1`'s; it minted nothing of its own and no test could reach it.
- MODIFIED AC-PLUG-008.1 -> docs/specs/plugin-loading.md : THE SYSTEM SHALL consider only the assemblies directly in the plugin directory — for the SDK version check, for eager loading of shared extensions, and when looking for a bound assembly — and SHALL treat an assembly that exists solely in a subdirectory as absent.
- MODIFIED AC-EMIT-013.2 -> docs/specs/emission.md : WHERE part of a stream's emission policy is the default THE SYSTEM SHALL omit that part from the report — the whole `runtime.throttle` entry where the policy is default throughout, `minChange` where the member declares no deadband, and `immediate` where it is false — comparing the declared `MinInterval` as a duration rather than as a spelling.
- MODIFIED AC-MODB-006.3 -> docs/specs/modbus.md : THE SYSTEM SHALL default the port to 502, and WHEN a port outside 1–65535 is set on a Modbus TCP client or on a hosted Modbus TCP server SHALL throw a `FormatException`.
- MODIFIED AC-SCEN-004.2 -> docs/specs/scenarios.md : THE SYSTEM SHALL require each comparator's comparand to take that comparator's shape — a number for `above` and `below`, a scalar or `null` for `equals` and `notEquals`, and a non-empty array of scalars for `oneOf` — SHALL treat a relational comparator as unsatisfied where the compared value or a resolved comparand is not a number, and SHALL satisfy a `oneOf` where the compared value equals any element under the same exact semantics.
- MODIFIED AC-CLI-001.1 -> docs/specs/cli.md : WHEN `--version` or `-v` appears before any command name THE SYSTEM SHALL print the tool's version and exit 0 without running a command.
- ADDED AC-CLI-001.11 -> docs/specs/cli.md : WHERE a command has already been named THE SYSTEM SHALL leave `--version` and `-v` to that command.
