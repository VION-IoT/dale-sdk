# IO area pass — the digital and analog I/O contract bindings

> Change doc — one in-flight change. The `Spec delta` below is distilled into the current-truth
> pages under `docs/specs/` in the implementation PR, then this doc is archived
> (`pwsh scripts/spec-change.ps1 archive <slug>`). Process: `docs/spec-process.md`. Never put

## At a glance

### Summary

The twelfth SDD area pass, over `Vion.Dale.Sdk.DigitalIo/` and `Vion.Dale.Sdk.AnalogIo/`: the four
faces a logic block binds to read an input or drive an output, the four provider faces a simulator
binds on the far side, the eight handlers that carry them over MQTT, and what the TestKits assume of
all of it. Phase A extracts the behavior table; Phase B mints the criteria, writes the page, fixes
what the operator classifies as a fix, and creates the area's first two test projects.

### Spec implications

Creates `docs/specs/io.md` (`D1`) — a new current-truth page, the thirteenth. It states the face
family, the four round-trips, the value contract, the handler protocol on the wire (registration,
decode, publish, the topic caches), the multiplicity and development-only declarations, the DI
registrations and the test discipline. It cites rather than re-mints: the binding attributes, the
contract base and the handler base (`AC-BIND-*`), the shared-assembly loading (`AC-PLUG-005.*`), the
introspection of the faces (`AC-INTRO-002.6`, `015.6`), the DevHost's pairing (`AC-SCEN-014.*`), the
analyzer reference (`AC-ANLZ-018.4`), and the actor's containment of a throwing handler
(`AC-LIFE-014.2`). No existing page changes except the roster in `docs/spec-process.md`.

### The value shape, and where it goes

A face carries a bare `bool` or a bare `double`. There is no unit, range, scale, deadband, debounce,
timestamp or quality flag anywhere in either project, and no constant to carry one
(`grep -rn "const \|TimeSpan\|Timeout\|default(" Vion.Dale.Sdk.DigitalIo Vion.Dale.Sdk.AnalogIo
--include=*.cs` → the builder size and nothing else). What reaches the wire is the value and its
contract identity, and nothing else.

### Who constructs the eight handlers

This is the join the DI row rests on, and it was read in the reader repositories on this machine.

- The **four consumer handlers** are registered as transients (`ConfigureServices.cs:17-18`) and
  constructed by the production runtime's scan.
- The **four provider handlers** are registered by nothing and constructed by nobody. The runtime's
  scan skips every `[DevelopmentOnlyHandler]` type before it creates an actor
  (`../dale/Dale/Reflection/LoadedTypeScanner.cs:80-94`), and the DevHost does not construct the
  shipped types at all — it discovers them by `[ScenarioWire]` and creates a generic
  `ServiceProviderContractHandler` stand-in registered under the handler's class name
  (`Vion.Dale.DevHost/DevLogicSystemInitializer.cs:374-399`). A repository-wide grep over `dale-sdk`,
  `dale` and `logic-block-libraries` finds the four provider handler names in exactly one place each:
  the `nameof(…)` on their own contract class.
- The runtime's "shared assembly left its handler actors unregistered" **Error** fires only where the
  assembly has no `IConfigureServices` at all (`../dale/Dale/Plugin/PluginLoader.cs:303-317`); both
  projects have one, so it never fires here. `architecture/libraries/dale-sdk.md:366` describes that
  Error and is confirmed, not contradicted.

So the three method bodies of each provider handler never run in any host. What those types carry is
declaration: `[ScenarioWire]` for the DevHost, `[DevelopmentOnlyHandler]` for the runtime's skip, and
a class name for `ContractHandlerActorName` to address.

### What the far side of the wire does

Read this session, in the reader repositories:

- `../hal-raspberry/Vion.Hal.Raspberry.dotnet/Handlers/DigitalOutputHandler.cs:166` reads the `Set`
  payload through `message.GetFlatBufferPayload(nameof(SetDoPayload))` — the **schema-checked**
  accessor of `../service-provider-sdk-dotnet/Vion.ServiceProvider.Sdk/Infrastructure/MqttApplicationMessageExtensions.cs:182-191`,
  which refuses an empty payload, a wrong content type, a missing schema property and a mismatched
  schema before decoding (`PayloadEmptyException`, `UnsupportedContentTypeException`,
  `MissingPayloadSchemaException`, `InvalidPayloadSchemaException`).
- `../hal-sim/HalSim/SimulationServiceProvider.cs:231,242-246` dispatches on that same schema user
  property.
- This area **publishes** the schema property (`DigitalOutputHandler.cs:75` passes
  `nameof(SetDoPayload)`) and **never reads** one — and cannot, because
  `Vion.Dale.Sdk/Abstractions/ServiceProviderMqttMessage.cs:28-96` exposes the topic, the response
  topic, the correlation id and the payload, and no user properties or content type.
- `../hal-raspberry` has no analog handler at all, confirming
  `../architecture/systems/hal-raspberry.md:94`.

That asymmetry is what rows 25–28 are about: the sender labels every payload and the receiver
decodes blind.

## Failure sketches for the ⚠ rows

**Row 16 — a block cannot see that its output goes nowhere.** A heat-pump block's SG-Ready contact is
left unmapped in the configuration; every `Set` is dropped at `LogicBlockContractBase.cs:119` and the
block reports healthy while the pump never moves. *Recommendation:* propose a public mapping
predicate on `LogicBlockContractBase` (`BIND`'s surface) and retire the consumer's reflection probe.

**Row 26 — an empty payload throws.** A broker redelivers a retained topic with a zero-length payload
(both HALs publish retained — `hal-raspberry/…/DigitalOutputHandler.cs:96,204` — so a retained-clear is
a live path); `GetRootAsDiStatePayload` throws `ArgumentOutOfRangeException`, `AC-LIFE-014.2` logs and
drops it, and an operator reads a stack trace naming FlatBuffers rather than the topic.
*Recommendation:* **fix** (classified). **Corrected at the classification:** the earlier sketch said
"refuses it by content type", which names a mechanism the inbound message does not carry —
`MqttMessageReceived` (`Vion.Dale.Sdk/Mqtt/ActorMessages.cs:79-84`) has `UserProperties` and **no**
`ContentType`. The guard is the schema verifier of row 27's sketch, which refuses an empty buffer
too.

**Row 27 — a truncated payload fabricates a value.** A publisher's buffer is cut short mid-message;
`Value` reads from the surviving vtable and the handler forwards `true` to every mapped block, which
acts on a value nothing sent. *Recommendation:* **fix** (classified) — `new Verifier(bb).VerifyBuffer(null,
false, <Payload>Verify.Verify)` before each decode; a `false` drops the message.
**Probe detail, corrected:** the two runs disagree on what the truncated payload's *string* field does —
this session's Phase A run saw `EndpointIdentifier` throw `ArgumentOutOfRangeException` (probe P3b, on a
56-byte `DiStatePayload` cut to 28), the classification's run saw `HardwareBlockInstanceId` return `''`.
The row's claim — a **value** read from a fragment, forwarded without a throw — is what both runs saw and
is what the fix addresses; the string field is read by nothing here (row 29).

**Row 28 — a foreign payload decodes as a plausible value.** A misrouted `AoStatePayload` carrying
`4.2` arrives on a digital-input topic and the handler forwards `true`; carrying `0.0` it forwards
`false`. *Recommendation:* fix, by reading the schema user property the publisher already sets — which
first needs it exposed on `ServiceProviderMqttMessage` (`BIND`), so propose the seam with the guard.

**Row 35 — the topic caches never shrink.** A long-lived output handler whose configuration is
re-linked many times keeps one entry per contract it has ever addressed, none of which is reachable
again. *Recommendation:* state the bound as intended, or clear both caches in an
`OnContractActorsLinked` override — one line, no observable change either way.

**Row 36 — the analog builder is two bytes short.** Every analog `Set` allocates a 20-byte builder for
a 24-byte payload and grows it once. *Recommendation:* fix — size each side for its own payload, in
both projects in one commit.

**Row 41 — the analog TestKit cannot verify a non-finite value.** A block writes
