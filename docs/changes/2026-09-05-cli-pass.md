**does** catch what a command action throws and returns 1 — so a `--project` pointing into a missing
directory is exit 1, not a CLR crash. But `Program.cs:38` runs *before* `InvokeAsync`, so the one
option value the parser refuses escapes as a genuine unhandled exception carrying the CLR's own exit
code. The area's exit-code alphabet is therefore **0, 1, `dotnet`'s passthrough, and one CLR crash
code** — the brief's "only 0 and 1" is right about the `return` statements and wrong about what a
script sees (row 12, Drift checkpoint 3).
