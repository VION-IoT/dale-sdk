# Review checks

One line per check: `Tn — name: what to look for, the shape of the violation`.
Two prefixes, numbered separately; a new check takes the next free number of its prefix; a number is never reused or renumbered.
`D` is closed: its checks were mined from the lead's own review findings over one window, and nothing is added to it. `P` grows by retro.
No quotes, dates or session ids in a check.
A check fires when a journal line names it. Unnamed for three retro rounds: deleted. Fires constantly: becomes a gate, removed here.

- D1 — Surface minimalism: every new attribute, option, public member, generator, wrapper or scenario-step kind traces to a consumer that exists now; a mechanism added for later, a shorthand duplicating a general path, or an explicit knob where a convention such as declaration order or a default already decides.
- D2 — XML docs terse and reader-facing: each doc claim matches the code that implements it rather than the neighbouring docstring; an RFC number, analyzer id, customer name, customer-specific example or design history in a doc, or a `<remarks>` restating the summary — which the docs site drops anyway ([`sdk-surface-conventions.md`](sdk-surface-conventions.md) § 2).
- D3 — Delete, don't deprecate: a generalised or replaced mechanism whose old path survives, or whose callers are not migrated in the same change; a field nullable or optional out of habit rather than for a live consumer.
- D4 — An author-facing rule ships with an analyzer: a constraint a library author can violate in C# enforced only by prose or a runtime throw, with no DALE diagnostic; a supported value type exempted in only one of `DALE003`, `DALE016` and `DALE008`; analyzer tests exercising rules only in isolation when their combination is what rejects valid code.
- D5 — The analyzer is proven to fire in a real build: an analyzer keying off a contract interface by symbol only, which the Metalama-hosted pipeline leaves unresolved, so it passes its unit tests and no-ops for every consumer; no test whose contract interface is genuinely unresolved, expecting `CS0246` beside the Dale diagnostic. A blocker, not a nit.
- D6 — Validated against a real consumer shape: a change proven only on the simple in-repo fixture, leaving untried a type in a different assembly, a component service on a property, two components of one type on one logic block, or a logic block with no service interface; guidance or examples an implementer would need, missing.
- D7 — Introspection verified from the packed artifact: a claim about emitted metadata read off the working tree or `tools/publish/*.json` rather than the JSON inside the package `dotnet pack` produced, or with no in-repo golden assertion behind it.
- D8 — Names are explicit and platform-aligned: an abbreviated platform noun (`provider` for `serviceProvider`, `block` for `logicBlock`), local vocabulary where a cross-repo one exists, or a type name that does not state its scope; a rename touching an introspection identifier ([`specs/introspection.md`](specs/introspection.md)) without saying so.
- D9 — Silence is a defect: an empty branch that drops a declaration, a no-throw test standing in for a round trip, a serialized `[]` where content was expected, or a mode-incompatible step that misbehaves instead of being refused; a deliberate fail-open that is not stated or does not log.
- D10 — Claims verified, mechanism explained: an assertion about current behaviour, a count or another repo with no `file:line` or command behind it; a verification story that does not say what ran, does not read `gh pr checks` after the last push, or asserts a DevHost change instead of demonstrating it; a fix that does not say why the defect slipped through. A fix reaching too few sites is P3; evidence true only of the shape it ran on is P4.
- P1 — Every count is pasted with its command: a number in a change doc, a REPORT or a pull request body that was re-read, carried from an earlier run or composed, instead of recounted at the head it describes.
- P2 — The reverse question, per anchor: an attribute, descriptor range, schema field or manifest entry the change touches with an observable behaviour that has neither a table row nor a criterion; a change doc's reviewer's question that describes an observable no row carries.
- P3 — The fix's siblings: a fix that closed the one symbol noticed rather than the defect's shape; a guard added to some arms of a `switch` and not every arm; previously inert inputs made live without every validator over them re-checked.
- P4 — Evidence is for the shape it ran: a probe's result claimed beyond the fixture shape and the surface it read (`get;` taken for `get; init;`, the definition view for the live view); a claim about another repository on this machine recalled instead of read there; a demonstrated DevHost row whose paste shows a scripted DOM write instead of the UI's own controls ([`devhost-conventions.md`](devhost-conventions.md) § 1).
- P5 — A green check is not evidence until something that should redden it does: a new test, criterion, gate rule or probe with no named production edit that fails it, or whose mutation was never run and that carries a citation instead of a `GAP:` with its reason — a fixture that cannot reach the clause, an Arrange and Assert naming the same declaration, a `_NoDiagnostic` test standing in for a behaviour claim, a `Contains` whose excluded substring contains its required one.
